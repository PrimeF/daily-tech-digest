### 3. "Decision models" become a cross-vendor category

Within a few days, several vendors converged on one primitive: models that **score a fixed set of answers in a single forward pass** instead of generating text, and return calibrated probabilities.

- **Google, Gemini Decisions API (11 Nov):** It runs on `gemini-decision-1` and evaluates up to 1,000 independent questions against one shared multimodal input of up to 256K tokens. There are three question types: `noul` (yes/no probability), `choice` (2–255 options) and `score` (ordinal rubric). Every answer carries a 0–1 confidence for routing to a fallback or a human. Google reports a median of 50–100 ms model compute and 150–250 ms end to end, nearly flat from 1 to 100 questions. Pricing is $0.10 per 1M input tokens and $0 for output, with the shared input billed once (vendor-reported) ([Google](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)). It was on the Hacker News front page with 400+ points.
- **Hugging Face, open decision models (10 Nov):** Transformers adds `pipeline("decision")`, `AutoModelForDecision` and a `/v1/systemone` endpoint in `transformers serve`, and llama.cpp serves the same API. HF proposes "State + Questions + Allowed Answers → Decisions + Probabilities" as a shared open interface, and notes that compatible autoregressive LLMs can be scored on answer-label logits without generating text ([HF blog](https://huggingface.co/blog/decision)).
- **Framework support:** langchain-core 1.8.0 (11 Nov) "adds decision models" ([release](https://github.com/langchain-ai/langchain/releases/tag/langchain-core%3D%3D1.8.0)). Haystack 3.5.0 (10 Nov) adds `OpenAIDecisionsTextRouter`, `OpenAIDecisionsImageRouter` and `OpenAIDecisionsDocumentClassifier` for OpenAI's Decisions API, which launched on 22 Oct ([release](https://github.com/deepset-ai/haystack/releases/tag/v3.5.0)).

**Why it matters:** Routing, guardrails, triage, rubric grading and agent tool selection are classification problems that teams currently solve with JSON-mode generation. A scoring API returns one forward pass, typed outputs and calibrated confidence, at a fraction of the cost and latency, and makes "confidence below threshold → escalate" a first-class design pattern. Expect agent harnesses to use it for the router and policy layers while keeping generative models for the work itself.

### 4. AWS releases an open-source local AWS Emulator

AWS launched [AWS Emulator](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-emulator-now-available/) on 11 Nov. Existing SDK and CLI calls are pointed at a local endpoint, so developers and **coding agents** can test without an AWS account or deployments. It is built in Rust as one crate per service, generated from AWS's published Smithy API models, so coverage grows as AWS publishes APIs. Unsupported operations return `501 Not Implemented`, and a per-service fidelity report compares responses with real AWS. Each instance gets its own port, keys and in-memory state, which isolates parallel agents and CI jobs. There is also an embedded per-test mode for Rust and an agent skill (needs AWS CLI ≥ 2.35.0). Telemetry is on by default and can be disabled. The source is CC0-1.0 (vendor code Apache-2.0), and the repo accepts issues but not PRs ([GitHub](https://github.com/aws/aws-emulator)). The repo had about 2.8k stars and 800+ points on Hacker News on launch day.

**Why it matters:** This competes directly with LocalStack and moto, with the advantage of being generated from AWS's own API models. For agentic development it gives coding agents a cheap, fast inner loop for infrastructure code. Treat it as a testing aid only: AWS says it is not for production or security testing, and IAM semantics and service fidelity should be checked against the published fidelity scores.

### Safety & Infrastructure

- **OpenAI Control Room (9 Nov):** OpenAI described a central kill-switch for **all research inference**, including RL sampling, evals and data processing. Every agentic research workload must have an approved safety case and gets a `job_id`. Inference engines ask Control Room for authorization on every request, so a stop from a monitor or a human halts output for that job on any engine. The worst-case stop latency is **35 s**, caused by an authorization cache. Enforcement sits in the inference layer rather than workload code, because there are few inference code paths. Agentic sweeps look for rogue engines, and the integration **fails closed**: if Control Room is down, all inference is denied ([OpenAI](https://openai.com/index/control-room)). *Architect takeaway:* this is a reusable pattern for any agent platform. Put a per-job authorization check at the model gateway, fail closed, and treat the cache TTL as your bound on kill latency.

## MCP & Agent-to-Agent (A2A)

- **MCP moves to a fixed six-month release cycle (11 Nov):** Spec releases now land on the last Tuesday of March and September. The **next spec is `2027-03-30`**. The process has a soft freeze 2.5 months before release (proposals must be Final), Tier 1 SDK betas at 1.5 months, and a hard freeze at 1 month (only critical fixes, by full Core Maintainer vote). Tier 1 SDKs must have stable support on release day, late proposals slip to the next release, and the spec date never moves. Wire format and version negotiation are unchanged. Luca Chang joins as Release Manager, and the process is documented in SEP-3398 ([MCP blog](https://blog.modelcontextprotocol.io/posts/mcp-release-cycle/)). *Implication:* platform teams can now plan MCP upgrades on a predictable twice-yearly cadence.
- **Experimental MCP file upload/download extension (10 Nov):** `io.modelcontextprotocol/files` targets protocol revision 2026-07-28+. Servers tag file arguments with `x-mcp-file`. For uploads, the server returns `upload_required` with a target URL and `requestState`, the client uploads directly and retries. Downloads are returned as targets in `_meta`. A per-target `credentials: omit|include` controls whether the MCP credential is sent. Open questions include an origin allowlist against exfiltration by malicious servers, replay protection, and whether `_meta` is the right home. It is a draft with no reference implementation yet; the authors expect to stabilize it by year-end ([MCP blog](https://blog.modelcontextprotocol.io/posts/exploring-file-uploads-and-downloads-in-mcp/)). The key design choice is that file bytes never pass through the model context.
- **Databricks Genie MCP server (11 Nov):** Databricks exposes governed business context to ChatGPT, Claude, Microsoft Copilot Cowork and Grok Bot as native plugins, and to any other client through the Genie MCP server. Charts and citations render only in clients that support the MCP Apps extension ([Databricks](https://www.databricks.com/blog/bring-your-business-context-chatgpt-claude-microsoft-copilot-cowork-and-grok-bot)).

## Engineering Blogs & Tech Press

- **Cloudflare, "Choosing QuePaxa, an unusual consensus algorithm" (11 Nov):** Cloudflare's experimental global control-plane store, Meerkat, uses QuePaxa instead of Raft or Multi-Paxos because leader-based protocols stall during WAN leader failures. Election timeouts are usually 5–10x RTT, about a second across continents, and split votes can turn into metastable failures. In QuePaxa the leader is an optional one-round-trip fast path. Other proposers keep making progress through randomized-priority rounds with small local hedging timeouts, and there is no dependence on failure detection. Trade-offs: extra bandwidth and proposals, termination guaranteed only eventually, and less battle-testing, so Cloudflare is formally verifying its Rust implementation and extending the protocol to crash-recovery. Vendor-reported numbers: over 95% of decisions on the fast path in normal operation; during a leader failure, throughput fell to about 65% of baseline and recovered in about a minute without halting ([Cloudflare](https://blog.cloudflare.com/choosing-quepaxa/)).
- **Meta, "How We Built TLX: A Hardware-Native GPU Compiler" (10 Nov):** TLX extends Triton with explicit orchestration: warp-group roles (producer, consumer, epilogue), mbarrier synchronization, TMA and TMEM memory control, and cluster/DSMEM execution. The rule is that Triton says *what* to compute and TLX says *how* to schedule it. It targets Hopper, Blackwell, MI300 and MI350, with MTIA in progress. Vendor-reported results: 20–25% end-to-end MFU training a large model on thousands of Blackwell GPUs, and up to 2x on the GDPA kernel. The post names no repo or license and gives no data for its "on-par with hand-tuned CUDA" claim ([Meta Engineering](https://engineering.fb.com/2026/11/10/open-source/tlx-a-hardware-native-gpu-compiler-for-production-ml/)).
- **Databricks, Genie Ontology benchmark (11 Nov):** The new Genie agent runs multi-step work unsupervised on an auto-extracted "ontology" of notebooks, dashboards, queries and docs. On a synthetic energy-company workspace built with Turing (hundreds of tables, 5 runs per task), Genie passed **91%** of tasks against 45% and 58% for two unnamed agents that used a Databricks toolbelt without the Genie MCP. It used less than half the tokens (vendor-reported; a single vendor-built benchmark, and the vendor notes smaller gains in young workspaces) ([Databricks](https://www.databricks.com/blog/genie-genie-ontology-delivers-16-accuracy-less-half-tokens); [TechCrunch](https://techcrunch.com/2026/11/11/databricks-new-ai-agent-tells-ceo-ali-ghodsi-the-unvarnished-truth/)). The architectural lesson: a curated semantic and context layer beats raw tool access for enterprise data agents.

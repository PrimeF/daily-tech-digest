### 2. Google ships Gemini 4 Hydrogen and "Orchestrator" multi-model handoff

On 12 Nov Google released **Gemini 4 Hydrogen** (`gemini-4-hydrogen`), the fast, low-cost tier of the Gemini 4 family. It joins **Gemini 4 Carbon** (frontier tier, released 10 Nov, not previously covered) and Gemini 4 Argon ([Google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)).

- **Hydrogen:** $1.50 / $7.50 per 1M input/output tokens, flat across a 1M-token context, with up to 1M output tokens. It has four thinking levels, including a new `xhigh`. Vendor-reported scores: Artificial Analysis Intelligence Index 51 (54 at xhigh, above Argon's 50), Terminal-Bench 4.1 57% (Gemini 3.8 Flash: 18.2%), HLE-Diamond 58.8%. Google says it is about 2.5x faster than 3.8 Flash and 2.3x more resilient to indirect prompt injection on Gray Swan's IPI benchmark. It is available in the Gemini API/AI Studio for all tiers, Gemini Enterprise, Antigravity, the Gemini app and Search. Vertex AI is not mentioned.
- **Carbon:** Google calls it its strongest model, aimed at long-horizon agentic work and cybersecurity. Introductory pricing is $2 / $10 per 1M tokens, rising to **$4 / $20 after 30 Nov**. Google reports #1 on CursorBench 4.0, Perplexity WANDR and Zapier AutomationBench, and a lower cyberattack-query success rate than Argon in Gray Swan testing (2.17% vs 9.86%) (all vendor-reported) ([Google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/)).
- **Orchestrator in Antigravity:** Carbon and Hydrogen **hand off to each other within a single task trajectory**, instead of a static router picking one model up front. Carbon does read-only exploration and planning with explicit re-planning triggers. Hydrogen executes (edits, package updates, tests) and hands control back to Carbon when it hits friction. On Terminal-Bench 4.1 Google reports near-Carbon success with about 24% less quota and 19% faster completion. The Antigravity SDK exposes the same pattern for explicit multi-model pipelines ([Antigravity blog](https://antigravity.google/blog/gemini-4-hydrogen-in-google-antigravity/)). The model announcement and the Orchestrator post both made the HN front page (about 520 and 400 points).

**Why it matters:** The planner/executor split used to be something you built yourself. It is now a vendor-managed, in-trajectory handoff. For platform teams this sets a cost baseline: a frontier model only for planning and repair, and a $1.50/$7.50 worker for most tokens. Budget for Carbon's price doubling on 1 Dec if you are piloting it now.

### 3. AI supply chain under attack: Fireworks AI breach reaches Notion; GitHub credential campaign targets CI and cloud secrets

- **Fireworks AI / Notion (12 Nov):** Fireworks, an inference platform for open models used by companies such as Cursor and Harvey, confirmed that an attacker **breached its cloud provider** and used that access to reach a Fireworks development system. The attacker took billing information and some datasets. This is Fireworks' second incident in two months. Notion says chat transcripts from Notion AI's **Insights** feature were taken: "any input to or output from the model that was written to the chat". Under 1% of workspaces may be affected, and the data mostly cannot be attributed to a specific customer. Notion disconnected from Fireworks on 3 Nov and deleted its stored data. Fireworks says the attackers are financially motivated and resell stolen LLM access ([TechCrunch](https://techcrunch.com/2026/11/12/cyberattack-on-fireworks-ai-allowed-hackers-to-access-notion-customers-chat-transcripts/); [Notion advisory](https://notion.com/help/security-incident-involving-a-third-party-ai-vendor), snippet only).
- **"wfx-loot" GitHub campaign (reported 12 Nov):** According to Aikido, an attacker used stolen credentials for **4,837 GitHub accounts** to probe 61,764 repositories for write access, starting 10 Nov. Secret theft is confirmed from at least 1,835 targets. The attacker opened "docs: dependency audit notes" PRs to test permissions, and about 92% were never noticed. The payload is a roughly 1,500-line stealer, delivered by modifying a workflow, adding a workflow on a short-lived branch, or planting an npm install hook. It **exchanges GitHub OIDC tokens for AWS, Azure and GCP sessions**, chains IAM roles into long-lived users, harvests AI provider keys, then deletes workflow runs and logs within a minute. About 50 compromised accounts can publish to npm, PyPI, Go, crates or Packagist, and two packages were already poisoned ([BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-compromise-4-800-github-accounts-to-steal-cloud-credentials/)). How the GitHub credentials were stolen has not been disclosed.

**Why it matters:** Both incidents target the same asset: **AI model access and cloud credentials sitting in third-party platforms and CI**. Concretely: scope cloud OIDC trust policies to specific repos, branches and environments (not `repo:org/*`); require approval for workflow changes from new branches; alert on gaps in workflow run numbers; and treat every inference vendor that stores prompts as a data processor whose cloud provider is part of your attack surface. Check for a `wfx-docs` branch and the probe PR.

### 4. AWS: next-generation AgentCore runtime becomes the default, and Cognito adds token exchange for agent delegation

- **AgentCore runtime V2 (12 Nov):** New Bedrock AgentCore runtimes now run each agent session in its **own Firecracker microVM restored from a snapshot** of an initialized agent. Sessions scale to 8 vCPU / 32 GB with images up to 10 GB, and scale to zero when idle. AWS reports P75 session start under 2 s for a 2 GB image (previously 29.7 s) and up to 68% less billed memory for multi-turn agents (vendor-reported). Existing runtimes stay on V1 until you set `platformVersion: V2`. It is the default in 19 regions, including Frankfurt, Ireland, London, Paris, Milan, Spain and Stockholm ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/new-agentcore-runtime-default/)).
- **Cognito OAuth 2.0 Token Exchange (12 Nov):** Cognito user pools now implement **RFC 8693**. A service or agent can swap a user's token for a down-scoped, single-audience token without a refresh token. When an actor token is supplied, Cognito adds an **`act` claim** naming the intermediary, so downstream APIs can tell agent-initiated calls from direct user calls. AWS's own example is an MCP server exchanging the user's token to call a backend API. It is available via the token endpoint or the new `GetDerivedToken` API on the Essentials and Plus plans ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-token-exchange/)).

**Why it matters:** Together these cover the two hardest parts of production agents: isolated, fast-starting compute per session, and **delegated identity** that does not forward the user's raw token. The `act` claim is the standard way to make agent actions auditable and policy-addressable. If you run MCP servers behind Cognito, this replaces custom token-minting code. Combined with AWS Emulator and Lambda MicroVMs (both covered 12 Nov), AWS is assembling a complete agent runtime stack.

### 5. Global Microsoft 365 outage

On 12 Nov, from 1:26 PM ET (18:26 UTC), Microsoft incident **MO1550821** degraded Exchange Online, Teams, SharePoint Online, Microsoft 365 Copilot and Defender XDR worldwide. Microsoft first cited elevated infrastructure load, then said it was "servers being unexpectedly unavailable; straining the remaining infrastructure" because a core process was overwhelmed. Mitigation steps: pausing all deployments, redistributing connection traffic globally, restarting servers, and considering reverting recent configuration changes. As of 6:57 PM ET recovery was only partial, and an earlier Teams incident (TM1550488, resource contention) may or may not be related ([BleepingComputer](https://www.bleepingcomputer.com/news/microsoft/massive-microsoft-365-outage-disrupts-outlook-teams-copilot-worldwide/)). HN threads reported Outlook still down roughly 12 hours later ([HN](https://hn.algolia.com/api/v1/search?tags=front_page)). No root cause has been published yet.

**Why it matters:** This is a classic capacity cascade: losing some servers overloads the rest. Copilot and Defender XDR went down with mail and chat, so AI assistants and security tooling share the blast radius of the productivity suite. Teams building agent workflows on M365 or Graph should design for degraded-mode operation and not assume Copilot is available during incident response.

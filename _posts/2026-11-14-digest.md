## Top Stories

### 1. Cloudflare: AI penetration-testing orchestrators have gone mainstream, and they chain stolen CI credentials

On 13 Nov Cloudflare published telemetry on LLM-driven offensive frameworks ([Cloudflare](https://blog.cloudflare.com/adapting-to-ai-penetration-testing-orchestrators/)). Key figures (vendor-reported, from Cloudflare's network):

- **Over 50 framework families** scanned Cloudflare customers in the last three days, from thousands of IPs, and the number is rising daily. Daily request volume from these tools is **up 30x since 1 Oct**.
- **ARTEX**, the open-source multi-agent pentest system whose creator removed the original repo on 8 Oct, now accounts for **over 60%** of known orchestrators. Cloudflare counts over 12,000 repositories and 204 public forks with code changes. The takedown caused a "hydra effect": instance counts accelerated after 8 Oct.
- The post compares five frameworks by architecture. Common patterns are a planner with parallel executor agents, **graphs of goals, leads and findings linked to an asset graph**, and Kali containers with root access. One (Cairn) dispatches work to existing coding harnesses (Codex, Claude Code, Pi). Tools plug in existing **MCP** servers to reach conventional pentest tools.
- **Incident pattern:** In several Cloudforce One investigations, attackers got into a hyperscaler environment and pivoted into the customer's Cloudflare account. The root cause was **static, non-expiring CI/CD tokens with broad cross-environment scope**. In one case an ARTEX instance used an account-level API token with no IP restriction to create Workers named `artex-*`, and issued about 400 database-dump requests in an hour.

This matches earlier independent reporting that ARTEX was used by a China-linked actor against more than 200 organizations from 17 Oct ([BleepingComputer, 2 Nov](https://www.bleepingcomputer.com/news/security/chinese-hackers-use-artex-ai-in-automated-attacks-against-200-orgs/)).

**Why it matters:** Together with the GitHub "wfx-loot" campaign covered yesterday, this is the second report in two days that **long-lived CI tokens are the entry point for automated, agent-driven lateral movement**. Cloudflare's recommended controls are WAF and rate limits, anomaly detection, bot defense, identity-gated access to admin surfaces with micro-segmentation, OpenAPI schema validation with mTLS, and threat intelligence. The most actionable step for architects is to replace static API tokens in pipelines with short-lived, IP- or workload-bound credentials. Agent harnesses are now dual-use infrastructure, so expect your own MCP-exposed tools to be probed by the same frameworks.

### 2. OpenAI launches ChatGPT Wallet: agents can now complete purchases

On 13 Nov OpenAI introduced **ChatGPT Wallet**. Its RSS summary calls it "a secure way for agents in ChatGPT Work, Codex, and dots to complete purchases with user approval and existing card protections" ([OpenAI RSS](https://openai.com/news/rss.xml); full article not readable, see Access Notes). Per TechCrunch ([TechCrunch](https://techcrunch.com/2026/11/13/chatgpts-new-wallet-lets-ai-agents-shop-and-check-out-for-you/)):

- **Availability:** a limited number of US ChatGPT Pro subscribers (18+) with US-issued Visa, Mastercard or Amex cards.
- **Flow:** you add a card once. The agent (a "dot") picks products. You review items, total and card, then approve with a biometric check (Face ID or fingerprint), which creates a transaction record.
- **Payment architecture:** the card is charged with a **network payment token**, so neither the agent nor the merchant sees card details. The merchant gets shipping and contact data from the agent. Card rewards and chargeback rights still apply.
- **Planned next:** spending limits and category or time-window pre-approvals for more autonomous purchases, and a **Commerce Partner Playbook** for retailers that want to support agent shoppers.

**Why it matters:** This is agent payments built on card-network tokenization with per-transaction human approval. Yesterday's Brave x402 item was the opposite model: stablecoin micropayments with no account. For enterprises the pattern to watch is the move from per-purchase approval to **policy-based pre-authorization**, which is effectively an authorization policy for agent spend. Retailer access is the open question: TechCrunch notes Amazon blocks AI agents, and United blocked agent bookings (covered 12 Nov).

### 3. Update: Nvidia fallout spreads to export controls and startup funding

**What's new since 13 Nov:**

- **The chip-forensics study is now mainstream evidence.** TechCrunch reported Will DePue's checkpoint-forensics findings (covered 13 Nov) as evidence that the leading Chinese open-weight models, including DeepSeek V4 and Moonshot's Kimi K3 releases, carry fingerprints of export-banned **Blackwell** GPUs. It adds Epoch AI estimates: about **2 million advanced chips** entered China in 2024–25 through schemes that hide their destination, and about **275,000 Nvidia accelerators** were imported into Malaysia. It also cites Bloomberg reporting that a company linked to Alice Huang (Megaspeed) smuggled banned chips to a Shanghai data center. TechCrunch stresses that offshore training would not necessarily break export law ([TechCrunch](https://techcrunch.com/2026/11/13/export-banned-nvidia-chips-are-behind-chinas-most-powerful-ai-models-uh-oh-jensen/)).
- **Startup funding gap.** PitchBook counts **105 Nvidia-participating rounds this year**, often as lead. Investors expect interim CEO Colette Kress to be "much more conservative", particularly on backing neoclouds, inference providers and open-weight labs. TechCrunch also mentions Nvidia's pending **$13B Hugging Face acquisition** (expected to close in 2027) ([TechCrunch](https://techcrunch.com/2026/11/13/jensen-huangs-departure-blasts-big-hole-in-ai-startup-funding-vcs-and-founders-say/)).
- **Credit guarantees under review.** According to a WSJ report summarized by TechCrunch, Kress had questioned Nvidia's credit-based guarantees to data-center operators that could not pay for chips up front, and had reduced Nvidia's planned commitment to OpenAI's Ohio project from $250B in credit to $105B ([TechCrunch](https://techcrunch.com/2026/11/13/jensen-huang-didnt-show-confidence-in-his-successor-report-says/)).

**Why it matters:** If Nvidia's vendor financing slows, the cheap neocloud capacity of the last two years (often GPUs half-funded by Nvidia equity) may get more expensive, or fewer new providers may enter. Architects with neocloud contracts should check provider funding exposure and capacity delivery dates before Tuesday's earnings call (17 Nov). An allegation that Nvidia "engineered scarcity" by funding startups reached the top of HN (about 450 points), but the source could not be read (unverified, see Access Notes).

### 4. LangChain raises $300M at a $3B valuation and repositions LangSmith as an agent platform

On 13 Nov LangChain announced a **$300M Series C at a $3B valuation**, led by CapitalG with GIC and DFJ Growth as new investors. That is more than double its $1.25B valuation of about a year ago ([LangChain](https://www.langchain.com/blog/series-c); [TechCrunch](https://techcrunch.com/2026/11/13/ai-agent-startup-langchain-hits-3b-valuation/)). LangChain says **over 7,000 organizations** use LangSmith, and that Clay monitors hundreds of millions of agent runs per month (company-reported). LangSmith is now structured in three parts:

- **Agent Runtime:** Deep Agents, LangGraph, LangChain, Agent Server, Sandboxes, Managed Agents and Fleet. Agent Server and Sandboxes can run in LangChain's cloud or in the customer's environment.
- **Agent Improvement:** observability, evaluation, **Engine** (an in-platform agent that finds errors in production traffic and proposes code and prompt fixes) and fine-tuning from traces.
- **Agent Governance:** LLM and tool gateways for budgets, fallbacks, data protection and tool authentication.

A product event follows on **20 Nov**.

**Why it matters:** The open-source framework company is now selling the control plane: runtime, sandboxes, gateways and an evaluation loop. That competes directly with AgentCore, Gemini Enterprise Agent Platform, Databricks Unity Gateway and Microsoft Foundry. The pitch is model and cloud neutrality ("own your intelligence"). For architects, the gateway layer (model budgets and tool authentication) is where vendor platforms now overlap most and where lock-in decisions will be made.

### 5. llama.cpp and ggml reach v1.0.0 with semantic-versioning guarantees

On 13 Nov the ggml-org team at Hugging Face tagged **llama.cpp v1.0.0** (`libllama`) and **ggml v1.0.0** (`libggml`) (tag verified with `git ls-remote`). From now on, **breaking changes to the public C API in `include/` require a major version bump**, backward-compatible features and new model or backend support are minor bumps, and bug fixes are patches. The project supports more than 150 architecture variants and all mainstream speculative-decoding methods. Distribution channels include Docker, Debian, Homebrew, conda-forge, MacPorts, Winget and an iOS/macOS XCFramework. CI runs on HF Jobs and Buckets, with self-hosted runners donated by NVIDIA, AMD, Qualcomm, Arm, IBM and Intel ([HF blog](https://huggingface.co/blog/ggml-org/llama-cpp-v1)). The ggml release reached the HN front page with about 210 points ([HN](https://hn.algolia.com/api/v1/search?tags=front_page)).

**Why it matters:** llama.cpp sits under Ollama, LM Studio and many edge and on-device products. Until now, downstream users pinned commit hashes. Stable ABI and versioning make it practical to ship it as a system library and to treat local inference as a dependency with an upgrade policy rather than a vendored snapshot.

## AI & Agentic AI

### Model Releases

- **Perplexity Decider v1.3 and Decider Flash v1.3 (12 Nov):** This follows the "decision models" category covered 12 Nov. Decider v1.3 is built on Qwen3.8-27B and Flash on Qwen3.5-4B (distilled with KL divergence). A marker token and a decision head trained on hundreds of public datasets return **probabilities** for classification, routing, ranking and evaluation. New in v1.3: bidirectional attention, and **"locate"** for span extraction (NER, PII, extractive QA). Vendor-reported results: query classification 91.6% (+6.54 points over Perplexity's production classifiers), retrieval nDCG@10 83.99 across 72 tasks (+1.81 over Qwen3-Reranker-8B), and answers changed on only 0.27% of questions under label perturbation (Jev 1.14: 2.69–4.84%). Weights are Apache-licensed on Hugging Face, and the models are also on OpenRouter and the Perplexity Decisions API ([Perplexity](https://www.perplexity.ai/hub/blog/perplexity-decider)). A permissively licensed decision model that also extracts PII spans is useful as a cheap router or guardrail in front of agent pipelines.

## Cloud Technologies

### AWS

- **Secrets Manager cross-account replication (13 Nov):** A primary secret can now be replicated to another account as an independent replica, encrypted with **a KMS key owned by the replica account**, with no shared KMS keys or cross-account resource policies. Replicas update on every rotation and can be promoted to standalone secrets. AWS positions this for central ownership by platform or security teams, and for isolated recovery accounts protected from ransomware or a compromised primary account ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/secrets-manager-cross-account/)). This removes a common reason for cross-account KMS grants.
- **AgentCore Identity accepts OAuth 2.0 authorization-server discovery URLs (13 Nov):** Inbound JWT authorizers and outbound OAuth credential providers can now use RFC 8414 metadata, not only OIDC discovery. This means authorization servers without OIDC can front AgentCore agents and MCP gateways ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/bedrock-agentcore-oauth2-discovery/)).
- **Security Hub CSPM via Organizations declarative policies (13 Nov):** Declarative policies are now the recommended way to enable Security Hub CSPM and select standards and controls per account and Region. Drift is enforced back to the policy, and new accounts get the baseline at creation. A console tool migrates existing central-configuration policies ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-cspm-org-policies/)).
- **Systems Manager Cloud Connector for Google Cloud (13 Nov):** The SSM Agent is auto-deployed to GCP VMs, so Session Manager, Patch Manager, Run Command and Inventory work across AWS, on-premises, Azure and GCP ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/systems-manager-google-cloud-support/)).
- **Coding-agent model routing with NVIDIA NeMo Switchyard (AWS ML blog, 13 Nov):** A CDK sample deploys LiteLLM with the open-source Switchyard plugin on Fargate, in front of Bedrock. **Stage routing** reads recent tool activity in the request history to choose between a capable model and a cheaper one, without a judge model. The post argues routing should be judged by **cost per solved task** (total spend divided by runs whose tests pass), not price per token. AWS labels switchyard-server 0.3.0 as demo-grade and not for production ([AWS ML blog](https://aws.amazon.com/blogs/machine-learning/route-coding-agent-requests-to-the-right-model-on-amazon-bedrock-with-nvidia-nemo-switchyard/)).
- Also 13 Nov: Aurora PostgreSQL express configuration in CloudFormation, AWS Batch on EKS security contexts (Linux capabilities, seccomp), and Grok 4.7 in Kiro on GovCloud ([AWS What's New](https://aws.amazon.com/about-aws/whats-new/recent/feed/)).

### GCP

- **Agent observability across BigQuery and Looker (dated 14 Nov):** A unified telemetry model: first-party Conversational Analytics agents emit telemetry automatically, and **ADK and LangGraph agents** stream the same structured telemetry into a customer-owned BigQuery table (`agent_events`) with one line of SDK instrumentation. Operational metrics and traces exclude prompts, responses and generated SQL. Full conversation logging is opt-in per agent and **fails closed**: logging is skipped when a knowledge source uses row-level security, policy tags or dynamic masking, while the chat session continues if logging fails. Now GA: agent-to-agent (**A2A**) workflows to BigQuery data agents in Gemini Enterprise, the Conversational Analytics API (with VPC-SC, CMEK and data residency), and Looker System Activity dashboards ([Google Cloud](https://cloud.google.com/blog/products/data-analytics/enterprise-ai-agent-observability-with-bigquery-and-looker/)). ### Multi-cloud / OSS and infrastructure incidents

- **Cloudflare Spend Management (beta, 13 Nov):** Hard spending caps for Workers and Durable Objects on pay-as-you-go plans, via dashboard, `cf` CLI or API. The architecture is a useful reference. Metering is aggregated near the source (1-minute, then 5-minute windows). An account-partitioned usage engine keeps local state plus a WAL. A rating engine holds unpriced usage as pending instead of treating it as free. Caps are enforced **asynchronously** through Quicksilver, so the billing path is never in the request path. Billable invocations (including Cron and Queue consumers) stop, but static assets keep serving ([Cloudflare](https://blog.cloudflare.com/spend-management/)). This is a direct answer to runaway agent or AI spend on serverless.

## MCP & Agent-to-Agent (A2A)

- **FastMCP 4.2.0 "Mad Skills" (13 Nov):** **Skills become a first-class server primitive.** A `Skill` is a validated value (name, description, instructions, files) that can be loaded from a directory or package, or built in code. It is served as ordinary MCP resources through `SkillCatalogProvider` or `SkillsDirectoryProvider`, discoverable through mounted servers and proxies, and readable with `Client.read_skill`. Dependencies can now be declared in annotations (`Annotated[dict, Depends(...)]`), and a new `KeystoneTokenVerifier` adds OpenStack Keystone auth. **Breaking:** Python ≥ 3.11 is required, and the 4.1 skills API is deprecated and will be removed in 4.3 ([FastMCP changelog](https://github.com/PrefectHQ/fastmcp/releases/tag/v4.2.0); version verified on [PyPI](https://pypi.org/pypi/fastmcp/json)). With GitHub's skills-packaging guide (covered 13 Nov), skills now have a standard way to be distributed over MCP rather than only as files in a repo.
- **Security:** Cloudflare's report (Top Stories) shows offensive orchestrators plugging in existing MCP servers to drive pentest tooling. MCP servers exposed to the internet need the same WAF, rate-limit and identity-gating treatment as any admin API.
- **A2A in production:** Google made A2A workflows to BigQuery data agents GA (see GCP). Spec: the `a2aproject/A2A` repo has a `v1.1.0-rc` tag, but it is dated 29 Oct and has no release notes, so nothing new in the window. `a2a-sdk` remains at 1.3.0 ([PyPI](https://pypi.org/pypi/a2a-sdk/json)).

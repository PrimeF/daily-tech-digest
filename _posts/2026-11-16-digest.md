## Top Stories

### 1. Alibaba releases Qwen4-Max: a new architecture, lower prices, and a closed flagship

On 16 Nov Alibaba's Qwen team made **Qwen4-Max** generally available by API, after a subscription-only preview last week ([Qwen blog](https://qwen.ai/blog?id=qwen4-max); [The Defiant](https://thedefiant.io/frontier/ai/alibaba-launches-qwen4-max-with-lower-api-prices)).

- **Architecture (vendor-reported):** a sparse MoE with a **2.4T-parameter backbone, 71B parameters active per token**, plus 328B "N-gram embedding" parameters. Native vision and a **1M-token context window**. Three new building blocks: Gated DeltaNet layers that compress history into fixed-size state for a sparse attention layer (QSA) that selects context blocks through a lightweight indexer; gated residual branches; and context-based n-gram lookups at layer 2. Alibaba says it activates 25% fewer parameters than Qwen3.8-Max.
- **Price:** **$1.50 input / $4.50 output per 1M tokens** (Singapore international rate), cache reads $0.075, 5-minute cache writes $1.875, 1-hour cache writes $3. Thinking and non-thinking modes cost the same, and there are **no input-length tiers** ([QwenCloud pricing](https://docs.qwencloud.com/developer-guides/getting-started/pricing)). The Defiant puts that at 25% below Qwen3.8-Max list prices and 70% below for cache hits.
- **Vendor-reported results:** 52.69 on Alibaba's own Work360 benchmark (Qwen3.8-Max: 47.74), with average cost per task down from $4.43 to $1.67 (62%). Token use on Terminal-Bench 4.0 is down about 48–49%. The comparison charts against other labs are images and could not be read (see Access Notes).
- **Independent data point:** Artificial Analysis lists Qwen4 Max at **43 on its Intelligence Index (rank 38 of 81)**, with a 984k context window and $3.27 per index task ([Artificial Analysis](https://artificialanalysis.ai/models/qwen4-max)). HN commenters (about 370 points) noted that this is below the top Western models and called the result modest for the parameter count ([HN](https://news.ycombinator.com/item?id=50513215)).
- **Agent features:** "Live Delivery" (the agent ships a usable first version early and then iterates while the user steers), released with an open-source plugin. The finance demo drives 90 MCP tools. Alibaba describes model, harness and product co-design with its Qoder IDE team.
- **Availability:** QwenCloud (API and Token Plan), QwenWork, Qoder and Qwen Studio. Global deployment is listed for Frankfurt, Hong Kong, Tokyo and US (Virginia). **Weights are not released.** Smaller Qwen4 models "are coming to open source", with no dates.

**Why it matters:** For architects, the interesting parts are price and context: flat pricing across a 1M window and a $0.075 cache-read rate undercut most frontier APIs for long-running agents, where cached input dominates cost. The caution is that the headline benchmark is the vendor's own and the one independent index score is mid-table. It also lands days after Cohere's and Microsoft's findings on open-weight Qwen checkpoints (covered 15 Nov), so the smaller open models will arrive under more scrutiny than earlier generations. Evaluate cost per solved task on your own workload before switching.

### 2. Update: Cursor's incident report shows how one leaked vendor key became a trojanized Claude Code extension

**What's new (Fireworks AI breach first covered 13 Nov):** On 13 Nov Cursor published its full account of the October incident, which was widely reported on 14–15 Nov ([Cursor](https://cursor.com/blog/security-incident-update); [BleepingComputer](https://www.bleepingcomputer.com/news/security/cursor-confirms-security-breach-led-to-malicious-claude-code-extension/); [The Hacker News](https://thehackernews.com/2026/11/stolen-fireworks-ai-key-led-to-cursor.html)).

The chain, per Cursor:

1. An attacker obtained an access key that **Cursor had issued to Fireworks** and that Fireworks exposed. It opened a read-only bucket used to share data for model training.
2. The bucket held coding-agent traces, mostly from 2025, from sessions not in Privacy Mode. **Some traces contained unredacted credentials** (less than 0.01% of customers had API credentials exposed; fewer than 0.05% of non-Privacy-Mode users had traces exposed).
3. Those credentials opened several SaaS tools: archived non-production source repositories, support emails, usage metrics, conversation summaries, and credentials that customers had sent to support.
4. On **29 Oct** the attacker used a stolen credential to write modified copies of Anthropic's Claude Code extension (`Anthropic.claude-code` 2.1.312 and 2.1.313) **directly into the cache that serves Cursor's VS Code extension marketplace**. They were live for about 11 hours, and at most 5,000 users could have received them. Open VSX, the upstream source, was never affected, and Cursor states this was not a vulnerability in Anthropic's product.
5. Per BleepingComputer, the payload tried to install an attacker SSH key and persistence. Coding errors likely stopped it working on many Windows and macOS machines without SSH enabled. Cursor says uninstalling the extension may not be enough and points to its remediation notice.

Cursor's response: all inference moved off Fireworks, every internal credential rotated, the marketplace rebuilt, all production infrastructure redeployed, network restrictions on vendor credentials, and secret scanning extended to internal data sources. The last attacker activity was seen on 1 Nov. Production systems, signed releases, customer repositories and Privacy Mode data were not affected. BleepingComputer adds that Wiz calls the wave of attacks on AI developer platforms "Black October" (Railway, OpenCode, Warp, Northflank and Lightning AI are named).

**Why it matters:** Each step is ordinary, and together they bypass most supply-chain controls. Three lessons: (1) **agent traces are a secrets store**: prompts, tool outputs and terminal logs kept for evals or training contain tokens, so scan and redact before they leave the production boundary; (2) a "read-only" share with a vendor is only as safe as its contents; (3) **caches and mirrors in front of a registry are part of the trust chain**, so verify signatures at install time, not only at publish time. Teams using Cursor should check for the two versions named above.

### 3. Update: FBI FLASH on ARTEX confirms AI-orchestrated intrusions at scale

**What's new (ARTEX first covered 14 Nov via Cloudflare's telemetry):** On 13 Nov the FBI issued **FLASH-20261113-001**, "Threat Overview of ARTEX Autonomous Penetration Testing Framework" (TLP:CLEAR, 13 pages), reported on 15 Nov ([BleepingComputer](https://www.bleepingcomputer.com/news/security/fbi-warns-artex-ai-hacking-tool-is-powering-global-cyberattacks/); [The Record](https://therecord.media/artex-ai-tool-fbi-flash-alert); [FBI PDF](https://www.ic3.gov/CSA/2026/261113.pdf), not fetched directly).

- **Speed and scale:** multiple actors have used ARTEX since at least August 2026. Some intrusions went **from initial targeting to privileged access in under three hours**. More than 1,600 ARTEX consoles were publicly exposed in early November (Censys, cited by the FBI), and the real number is believed to be much higher.
- **Models:** ARTEX has no model of its own. Per The Record's quotation of the advisory, attacker-run instances mostly use Chinese models, led by the DeepSeek Flash family, because of capability, low cost and "lack of observable guardrails when framed for penetration testing". Provider-side guardrails are therefore not a control defenders can count on.
- **Named campaigns (per BleepingComputer):** a ConnectWise supply-chain compromise with at least 162 tenants compromised and authentication attempts against more than 2,250 downstream Microsoft 365 tenants; data on about 67,000 people stolen from South Korean financial institutions; and a campaign against more than 200 organizations in 14 countries.
- **Targets:** systems that get little security attention: partner and supplier portals, mobile backends, employee apps, legacy services, third-party integrations. No zero-days are involved. The agents chain known weaknesses and "map trust relationships between organizations" to enter through weaker vendors.
- **Mitigations:** restrict cloud admin interfaces, review application permissions and sign-in logs, rate-limit sensitive APIs, and watch for bursts of automated requests and unexpected credential changes. MalwareMustDie released an open-source detection signature pack the same day.

**Why it matters:** Cloudflare's numbers showed volume, and the FBI now adds confirmed victims and timing. Three hours to privileged access is shorter than most alert-triage SLAs, so detection has to be automated and containment pre-authorized. One practical signal: outbound calls to LLM API endpoints from servers with no reason to make them.

## Engineering Blogs & Tech Press

- **Anthropic, "Solving code review at Anthropic" (post dated 15 Oct; covered by InfoQ 15 Nov, not previously covered):** How the Claude Code team reviews a codebase that is about 90% agent-written ([Anthropic](https://claude.dev/blog/solving-code-review-at-anthropic/); [InfoQ](https://www.infoq.com/news/2026/11/claude-code-review/)). Reusable design:
  - **Risk sets the tier, not the author.** A classifier assigns zero, one or two human approvals. A second classifier asks whether this particular change needs a person anyway. CI workflow files and owner-listed paths always need a human. Agent approvals never count as human approvals, and an approval covers one specific commit.
  - **Review pipeline:** parallel bug-hunting agents, then a separate group of verifiers that vote on each finding. Only findings with enough agreement are posted. A separate security review can block the merge.
  - **Convergence controls:** a cap of three review rounds, diff-only re-review, and no repeated findings. The cause: in one PR with more than 50 rounds, about 59% of the flagged code predated the first review.
  - **The reviewer is evaluated daily** against a set of past incident and revert PRs. Prompt or model changes are kept only if the score rises.
  - Vendor-reported results: merged PRs more than doubled from June to September while the revert share fell by over 40%. PRs passing after one review-and-fix round rose from 65% to 78%, and those needing five or more rounds fell from 8.9% to 1.5%.
- **Uber Engineering, "Securing AI Agents" (post dated 6 Nov; covered by InfoQ 15 Nov):** Identity and API authorization "can't determine whether an agent's proposed action is appropriate in context", so Uber adds **behavioral authorization** on the classic PAP/PDP/PEP model ([Uber](https://www.uber.com/us/en/blog/securing-ai-agents/); [InfoQ](https://www.infoq.com/news/2026/11/uber-secure-ai-framework/)). The **AI Registry** (policy administration) records each agent's owner, persona, permitted intents, constraints and risk class. **AI Guard** (policy decision) evaluates proposed actions. **Agent Guard** hooks (enforcement) intercept agent and tool execution. Before deployment, **Argus** scans code, prompts, configurations and tool paths, and the same checks apply to MCP servers. After deployment, unified traces let recorded traffic be **replayed against new policies** before rollout. Uber's main lesson: generic thresholds failed, and explicit per-agent intents and constraints worked best. Trade-offs named: inline latency, false positives and per-agent setup effort. No numbers are published.
- **Databricks, "Teach Genie One your workflows" (dated 16 Nov):** Genie One skills use the open Agent Skills format (a folder with `SKILL.md`). Through **Unity Gateway Skills (beta)** a published skill becomes a Unity Catalog object with permissions, tags and audit, and can be used by any MCP-compatible agent, including coding agents. Skills can run on a schedule, and the instructions must say what to do at review points when nobody is present ([Databricks](https://www.databricks.com/blog/teach-genie-one-your-workflows-ultimate-guide-skills-genie-one)). Governing skills in the data catalog is a pattern to watch.

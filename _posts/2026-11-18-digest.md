### 1. OpenAI releases GPT-6.2 Astra and GPT-6.2 Sol

**What happened.** On 17 Nov OpenAI released GPT-6.2 Astra (the frontier tier) and GPT-6.2 Sol (the fast, cheaper tier) in ChatGPT Work, Codex and the API. OpenAI's summary promises "better professional outputs, coding, computer use, and efficiency at lower cost" ([OpenAI RSS](https://openai.com/news/rss.xml); the article itself is not readable). Both models went GA on Amazon Bedrock the same day ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/openai-gpt-6-2-astra-sol-amazon-bedrock/)), and Microsoft says GPT-6.2 is "coming to Foundry" ([Microsoft](https://blogs.microsoft.com/blog/2026/11/17/ignite-2026-building-the-frontier-ecosystem/)). It was the top Hacker News story of the day, at about 1,260 points ([HN](https://news.ycombinator.com/item?id=50535230)).

**Pricing (per 1M tokens, from The Decoder and Artificial Analysis):** Astra costs **$8 input / $0.40 cached / $40 output**, 20% less than GPT-6 Astra; cached input fell from $1.00. Sol is unchanged at **$2 / $0.10 / $10**. Astra's Ultrafast mode is listed on Bedrock for latency-sensitive agents.

**Independent evaluations:**

- **Artificial Analysis:** Astra is **#2 on the Intelligence Index** (62 per The Decoder), behind Claude Fable 5.2 (65) and ahead of Gemini 4 Carbon (60) and Claude Opus 5.5 (59). Sol scores 57, level with GPT-6 Astra at about 15% of the cost per task ([Artificial Analysis](https://artificialanalysis.ai/articles/openai-has-the-2-model-in-the-intelligence-index-with-the-release-of-gpt-6-2-astra-and-gpt-6-2-sol)).
- **Coding has stalled:** On AA's Coding Agent Index (Codex harness, max effort), Astra is flat against GPT-6 Astra. Sol drops 3 points, mostly from a 14-point fall on SWE-Atlas-QnA-AA, where it leaves out key facts more often. AA-Omniscience hallucination rates at max effort are 59% for Astra and 55% for Sol, measured on deliberately hard questions.
- **Vals AI (via The Decoder):** Astra ranks 7th and Sol 9th on the Vals Index, at $10.68 and $3.18 per task. Astra uses the fewest output tokens in the top 10 (about 91k per task).
- **Epoch AI (via The Decoder):** ECI 174 for Astra, tied with Fable 5.2. Astra solved 7 of 68 FrontierMath Erdős problems, all verified in Lean. The previous record was 3.

**Safety (from The Decoder's reading of the system card):** both models reach the **"Critical" cybersecurity threshold** in OpenAI's Preparedness Framework. Astra is the first externally released model at the **"High" AI self-improvement** threshold. OpenAI adds stricter cyber safeguards, which it says will also limit some legitimate security research, and plans vetted researcher access through "Daybreak" ([The Decoder](https://the-decoder.com/openai-launches-gpt-6-2-astra-and-sol-with-lower-api-prices-and-some-benchmark-gains/)).

**Why it matters.** The trend from last week's Databricks AI Index holds: price-performance moves faster than peak capability, and frontier coding scores have flattened. Treat this as a cost re-baseline, not an automatic upgrade. Sol's SWE-Atlas regression shows why you should replay your own traces before switching defaults. The "Critical" cyber rating, together with Java4Shell (Top Story 3), means your security-research workloads may hit new refusals.

### 2. Microsoft's `agent-framework` package was hijacked on PyPI

**What happened.** Two malicious releases of `agent-framework`, the PyPI meta-package for Microsoft Agent Framework (the successor to AutoGen and Semantic Kernel), went up on 17 Nov: **1.26.1 at 20:35 UTC** and **1.26.2 at 21:08 UTC**. Both were gone by about 21:20 UTC, and 1.26.0 (12 Nov) is again the latest version. PyPI's index now lists nothing after 1.26.0 ([PyPI](https://pypi.org/project/agent-framework/)). Socket, Aikido and Endor Labs flagged the releases ([Socket](https://socket.dev/blog/agent-framework-pypi-package-compromised-with-credential-stealer); [Aikido](https://www.aikido.dev/blog/two-malicious-agent-framework-releases-hit-pypi-in-33-minutes)).

**How the payload works (per Socket and Aikido):**

- The attacker repacked a legitimate wheel, likely by hand, and uploaded it with valid publishing credentials. How those credentials were obtained is not known. Both releases were wheel-only, with no sdist, which differs from Microsoft's normal releases.
- A `.pth` startup hook runs on **every Python interpreter start**, even when the package is never imported. The collector forks with `setsid()` on Unix and runs as a daemon thread on Windows.
- It harvests environment variables matching TOKEN/SECRET/KEY/AZURE/AWS/GITHUB, `/proc/*/environ` from up to 300 processes, credential files (Azure CLI, Azure DevOps agent, pip, npm, netrc, Git, Docker, Hugging Face, `.env`), managed-identity tokens for 12 Azure resources via IMDS (169.254.169.254), and Azure DevOps OIDC tokens. **1.26.2 also requests GitHub Actions OIDC tokens**, so workflows with `id-token: write` are exposed.
- The data is zlib-compressed and base64-encoded, then POSTed to `webhook[.]site/d381fd80-…`. Version 1.26.2 restores the original `__init__.py` byte for byte, so integrity checks on that file alone miss it.
- **IOCs:** `agent_framework_meta.pth`, `af_runtime_diag.pth` or `af_runtime_diag.py` in site-packages; `_AF_TEL=1` in process environments; User-Agents `af-runtime-diagnostics/1` and `runtime-diagnostics/1`. Wheel SHA256 hashes are in the Socket and Aikido posts.

**Fallout.** Hours later the `microsoft/onnxruntime` and `microsoft/agent-framework` GitHub repositories began returning 404, along with at least seven related ONNX repositories. Microsoft has not given a reason, and any link to the PyPI incident is so far only speculation from Hacker News commenters. ONNX Runtime packages on PyPI, NuGet and Maven Central still install, but source builds and anything that downloads GitHub release assets are broken ([HN, about 306 points](https://news.ycombinator.com/item?id=50539610); [onnx/onnx #8842](https://github.com/onnx/onnx/issues/8842)).

**What to do.** Pin `agent-framework==1.26.0` with hashes, and remember that a range like `>=1.26` would have pulled the malicious versions. Rebuild any CI cache or image built after 20:35 UTC on 17 Nov. Rotate every secret those runners could reach, and check Entra sign-in logs for the affected service principals and federated credentials. Endor Labs advises against running `python` or `pip` in a suspect environment first, because the hook fires on interpreter start. The broader lesson: agent-framework installs typically run in CI next to cloud OIDC tokens and model-provider keys, which makes these packages unusually valuable targets.

### 3. Java4Shell: an AI-assisted find becomes pre-auth RCE across the Java ecosystem

**What happened.** On 17 Nov, Calif disclosed **CVE-2026-114938** ("Java4Shell"), and Oracle and OpenJDK shipped fixes at 13:00 PT ([Calif](https://calif.io/java4shell/)). It was the second-highest HN story of the day, at about 900 points.

**Technical details:**

- **Root cause:** the bug is in HotSpot's x86-64 **AVX-512 VBMI Base64 decoder intrinsic**. For padded input, the output length underflows to a negative value, the write mask becomes all ones, and 64 bytes go into a 50-byte buffer. Java rejects the input only after the heap is already corrupted. The trigger is 64 `A` characters followed by `=` (128 on OpenJDK 17).
- **Scope:** OpenJDK **17.0.6 and later** and every downstream build (Oracle, Corretto, Temurin, Microsoft, Zulu, Liberica, SapMachine, Red Hat, GraalVM). Only x86-64 CPUs with AVX-512 VBMI are affected: Intel Ice Lake through Granite Rapids, AMD Zen 4 and later. **ARM64, including Graviton and Cobalt, is not affected.**
- **Impact:** Calif demonstrated **unauthenticated RCE** in default configurations of Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate, and **authenticated RCE** in Kafka brokers, Solr, Elasticsearch, Gerrit and Spinnaker. A client-side variant hits Java programs that open TLS connections to a malicious server. Each exploit has to be tailored to its target and depends on heap grooming and network timing. Per-product exploit chains are being withheld for now.
- **Severity:** CVSS 4.0 9.2 according to Calif; Oracle rates it CVSS 3.1 8.1 ([BleepingComputer](https://www.bleepingcomputer.com/news/security/critical-java4shell-flaw-allows-rce-attacks-on-major-java-applications/)).
- **Discovered with Codex:** Quang Luong pointed OpenAI's Codex at the JIT intrinsics. Finding the bug took about an hour and a first exploit two more hours, for under $200 in tokens. Calif says AI agents built most of the follow-on exploit chains.

**Patches and mitigations.** Amazon shipped Corretto **27.0.1.1.4, 25.0.5.1.2, 21.0.13.1.2, 17.0.21.1.2, 11.0.33.1.1 and 8u514** ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-corretto-nov-2026-updates/)). If you cannot patch immediately, start the JVM with `-XX:-UseBASE64Intrinsics`, or with `-XX:UseAVX=2` on x86-64 only (ARM JVMs will not start with that flag). Calif warns that nginx request buffering does not stop the Elasticsearch chain.

**Why it matters.** This is the patch-to-exploit compression from GTIG's tracker (covered 17 Nov), now seen from the defender's side: one researcher with a coding agent turned a hardware-specific intrinsic into a cross-vendor RCE in an afternoon. Inventory self-hosted Java services on recent Intel and AMD fleets first, especially identity providers (Keycloak, PingFederate) and CI (Jenkins). Moving those services to ARM instances removes this particular exposure.

### 4. Microsoft Ignite 2026: an agent control plane, with MCP as a governed surface

**What happened.** Ignite opened on 17 Nov with the Copilot "OS for work" pitch (Chat, Cowork, Code, Autopilot), but the architecture news sits in the Book of News ([Microsoft](https://blogs.microsoft.com/blog/2026/11/17/ignite-2026-building-the-frontier-ecosystem/); [Book of News](https://news.microsoft.com/events/ignite/2026/book-of-news/)). Office Watch counts only **76 of 215 announced features as available today** ([Office Watch](https://office-watch.com/2026/microsoft-ignite-2026-ready-today/)), so check the status labels:

- **MCP Firewall (preview, Entra Global Secure Access):** policy over MCP servers, tools, resources, prompts, protocols and transports. This is the first hyperscaler network-layer control built specifically for MCP.
- **Microsoft MCP Server for Enterprise (GA):** gives agents permission-scoped access to Entra data.
- **Agent 365:** governance of MCP servers registered in Azure AI Gateway and third-party gateways such as **LiteLLM** (preview); observation of local and "shadow" MCP servers (preview); and **Dynamic Agent Risk** scoring (preview), which combines identity, data, endpoint and network signals with partner feeds from Check Point, Cyera, Darktrace and Zenity. Microsoft says more than 50 million agents are already registered.
- **Entra Agent ID for discovered local agents (preview):** separate identities are assigned automatically, starting with **GitHub Copilot CLI and Claude Code**, so agent activity can be told apart from human activity.
- **Foundry Agent Service is GA**, with managed identity and authorization, tracing, evaluations and safety controls. Multi-turn evaluation and Agent Optimizer are GA. **Foundry on AKS** (preview) deploys open-weight models and agents into your own clusters, and an **Agent Sandbox extension for AKS** (preview) runs agent-written code in VM-isolated sandboxes, Microsoft's answer to AWS Nitro Sandboxes (covered 17 Nov).
- **Models:** **MAI Code 2** is GA in GitHub Copilot, and **MAI Code 2 Flash** is in limited preview in Foundry. Microsoft claims Code 2 reaches 98% of GPT-6.1 Sol's performance at 40% of the cost, and 96% of Claude Opus 5.5's at 5% of the cost, averaged over DeepSWE 1.1, Terminal Bench 2.1, SWE-Atlas and FrontierCode v1.1. These are vendor-reported figures at a 50% promotional price, measured in Microsoft's own Copilot CLI setup ([Microsoft AI](https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/)). **Microsoft-Decision-1.1**, a routing and classification model built on Gemma 4 26B A4B, is GA in Foundry, OpenRouter and Vercel.
- **Infrastructure:** **Cobalt 200 VMs are GA** (vendor-reported: up to 50% faster than Cobalt 100; 24 regions by year-end). Microsoft claims **Maia 300** delivers 40% more tokens per watt than GPU systems but gave no availability date. **Azure HorizonDB** (PostgreSQL-compatible) is GA.

**Why it matters.** Microsoft is building agent governance at the identity and network layers (Entra, Global Secure Access) rather than in the frameworks. For multi-cloud architects, the LiteLLM gateway integration and the automatic Agent IDs for Claude Code and Copilot CLI are the most portable pieces. The MCP Firewall is preview only, so do not plan around it yet.

## MCP & Agent-to-Agent (A2A)

- **Spec status:** nothing new. - **FastMCP 4.2.1 (17 Nov)** is a security patch. It rejects JWTs with a future `nbf`, keeps provider `required_scopes` when a custom token verifier is used, pins pre-registered OAuth clients to their issuer, hardens the OAuth proxy's consent and claims handling, and raises the `opentelemetry-api` minimum to fix a traceparent ReDoS. Users with `require_authorization_consent="remember"` will be asked for consent again ([GitHub](https://github.com/PrefectHQ/fastmcp/releases/tag/v4.2.1)). Upgrade any FastMCP server that sits behind the OAuth proxy.
- **GitHub's Agent Host Protocol (AHP):** a new open protocol that lets any client (VS Code, the Copilot app, phones) attach to and continue the same agent session. Each channel is identified by a URI and holds **server-authoritative, reducer-based state** driven by an ordered action log. Clients apply actions optimistically and replay queued actions on reconnect. An optional channel carries MCP additions, and custom methods plus `_meta` work as escape hatches in the same way they do in MCP. There are two independent hosts, VS Code's in TypeScript (about 369k lines) and GitHub's in Rust (about 305k lines), with libraries in six languages. The spec is at microsoft.github.io/agent-host-protocol ([GitHub Blog](https://github.blog/engineering/engineering-principles/building-the-agent-host-protocol-for-sessions-that-continue-across-devices/)). AHP covers client-to-agent-host session sync. It complements MCP (tools) and A2A (agent to agent), not replaces them. The post does not specify the wire format, authentication or conflict-resolution rules.
- **Community:** `ag-ui-protocol/ag-ui` (Agent-User Interaction Protocol, about 20.2k stars, +1,445 today) is back on GitHub trending ([GitHub trending](https://github.com/trending)).

Caveats: open models only, one provider, and ±10-point confidence intervals. Claude Code was not tested. Takeaway: pick the model first, then benchmark harnesses for that model, and cap steps.

## Engineering Blogs & Tech Press

- **Databricks, "How we raised Databricks cluster rate limits by 7.5×" (18 Nov):** a fixed request-rate limit fits long-running async workflows badly. It is too strict when there is spare capacity, and it cannot see retries from work it has already accepted, which is how retry storms keep an overload going ([Databricks](https://www.databricks.com/blog/how-we-raised-databricks-cluster-rate-limits-75)).
  - **New design:** accepted requests wait in a **bounded queue** for a **slot**. A slot covers the whole provisioning workflow, background work included, not just the API call. **Adaptive concurrency limits** shrink when provisioning latency and thread-pool saturation rise and grow back slowly, and **fair scheduling** decides how tenants share capacity. The old request-rate limit stays as a last guardrail.
  - **Failure modes they designed for:** unbounded queues that turn a blip into hours of delay (so waits are bounded and work that can no longer finish expires); expensive mass expiry (queue entries are kept small); and throttling blamed on customers when the service caused it (throttles are attributed separately).
  - **Results (vendor-reported):** 7.5x higher default limits, more than 99.99% fewer rate-limit errors, and more than 100 per-customer overrides removed. The trade-off is that a successful API response no longer means an immediate start. The same pattern applies to any agent or LLM gateway fronting slow, rate-limited providers.
- **GitHub Engineering, "Building the Agent Host Protocol…" (17 Nov):** see MCP & A2A. The design lesson for architects: model agent sessions as an LSP-style protocol with server-authoritative reducer state, not as client-owned chat transcripts.

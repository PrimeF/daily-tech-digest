## Top Stories

### 1. A Claude-assisted Lean proof of the Riemann Hypothesis passes community verification

**What happened.** On 20 Nov, Anthropic mathematician Levent Alpöge released a Lean-only proof of the Riemann Hypothesis, about 17 million lines, that he says he found "working with Claude"; he adds that the method extends to the Generalized Riemann Hypothesis ([Alpöge](https://alpo.ge/remark.pdf)). Terence Tao describes it as an enormous Lean-only GRH proof generated with an internal AI model ([Tao](https://terrytao.wordpress.com/2026/11/20/unforced-euler-singularity-unforced-navier-stoke)). On 21 Nov the Lean and Mathlib communities certified both statement and proof: the theorem was compared with Mathlib's existing `RiemannHypothesis` definition using `comparator` and `con-leche --compare`, and the exported proof was checked by Lean's kernel, `con-leche`, `con-ron` and third-party checkers. Dozens of people compiled it independently, and the library depends only on Mathlib ([Lean community](https://leanprover-community.github.io/blog/posts/riemann-hypothesis/)). It was the top Hacker News story of the window (about 2,900 points); last30days counted 12 related HN stories (about 4,800 points) and YouTube explainers with about 3.8M views.

**What is still open.** Nobody yet understands the argument. Alpöge says it is "incredibly long", that a generated human-readable version ran past 250,000 pages, and that he will now work on a proper write-up. Early Zulip analysis suggests it draws on the Langlands programme and automorphy lifting ([TechCrunch](https://techcrunch.com/2026/11/20/ai-claimed-a-solution-to-the-167-year-old-riemann-hypothesis-and-a-human-did-too/)). Scott Aaronson calls it correct and notes that no AI result carrying a Lean certificate has yet been retracted ([Aaronson](https://scottaaronson.blog/?p=10344)). The same day, Alpöge, Tristan Buckmaster and Matei Coiculescu released finite-time blow-up proofs for the unforced 3D Euler and Navier–Stokes equations, also formalized in Lean (per Tao). A competing all-human GRH draft by Stanford postdoc Alessandro Masullo, posted by Ravi Vakil, drew reports of problems within hours, several found with AI models ([Vakil](https://math216.wordpress.com/2026/11/20/hurried-announcement-alessandro-masullo-grh/)).

**Context.** Anthropic reported on 17 Nov that agents running Claude Fable 5.2 settled two open problems in black-hole physics, with the modular-bootstrap results verified in Lean ([Anthropic](https://www.anthropic.com/research/claude-black-hole-physics)). OpenAI's chief scientist wrote that its models began producing "groundbreaking" maths at a log-perplexity of about 0.76 (see AI & Agentic AI).

**Why it matters.** This is the clearest case yet of trusting a machine-generated artifact that no human can review, because a small trusted checker verified it. Most of the community's effort went into confirming that the Lean *statement* means what mathematicians mean, which is where the residual risk sits. The same architecture applies to agent output in production: let agents produce large artifacts, gate them on machine-checkable certificates (type checkers, formal specs, property tests), and spend human review on the specification rather than the output.

### 2. Update: Amazon documents Cairn agents finding and exploiting a zero-day on their own

**What's new (Cairn first covered 17 Nov in GTIG's tracker).** Amazon Threat Intelligence published a first-hand case on 20 Nov ([AWS Security Blog](https://aws.amazon.com/blogs/security/chinese-nexus-actors-cairn-ai-agents-found-a-zero-day-on-their-own/); [The Register](https://www.theregister.com/security/2026/11/20/china-attackers-deployed-ai-agents-that-autonomously-found-and-exploited-a-0-day-to-take-over-a-university-server/5311382); [The Hacker News](https://thehackernews.com/2026/11/attackers-ai-agents-found-zero-day-in.html)):

- **How Amazon saw it:** the operator left the Cairn control panel online without authentication (found 10 Sep), exposing prompts in Simplified Chinese, configurations and agent output. The campaign ran for about 48 hours from 8 Sep against East Asian universities. Attribution to a China-nexus actor is moderate confidence.
- **The brief:** one instruction, "obtain shell access". The agents chose methods themselves.
- **Failures first:** 148 actions over 16 hours against an unauthenticated Redis server (replication-based code loading, sandbox escape, Log4Shell, an SSRF in a co-located Qdrant to map Docker subnets), then credential sprays; a separate six-hour spray hit a GPU server using about 80 usernames harvested from public pages.
- **The zero-day:** in MONAI Label (0.8.5 and earlier), an open-source medical-imaging annotation server, the agents found a path traversal in an upload filename parameter and reached arbitrary file write in about 11 minutes. A later session wrote a reverse shell into `sitecustomize.py` and triggered a training job, which returned a root shell. The Hacker News lists it as CVE-2026-133968 (CVSS 9.8). The operator then gave the agents a tunnel into a second university running the same software.
- **Fix status:** an advisory exists (GHSA-qc22-rmgc-vg94) and a source fix was merged on 19 Oct, but The Hacker News reports no patched release. Treat installs as unpatched unless built from source.

**Why it matters.** The successful target was niche research software with authentication off by default, the long tail of AI and ML tooling (labelling servers, vector databases, notebook and training endpoints) that rarely gets pentested. Agents search that long tail cheaply and tirelessly. Inventory internet-reachable ML tooling, enable authentication, never run it as root, and alert on writes to Python startup hooks (`sitecustomize.py`, `.pth` files), the same persistence trick used in last week's `agent-framework` PyPI compromise.

### 3. OpenRouter off-boards three inference providers after canary tests catch data mishandling

**What happened.** On 22 Nov OpenRouter disclosed that researchers at Dragos ran canary-token tests against inference providers and found data compromised, or data policies not upheld, at some of them. OpenRouter off-boarded three providers (not named), removed **125 endpoints from Zero Data Retention (ZDR) eligibility**, including some removed as a precaution, and notified potentially affected customers. It says it will run the canary tests continuously, verify network paths for forwarding to third parties, and require validation before restoring ZDR ([OpenRouter](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/); [The Hacker News](https://thehackernews.com/2026/11/openrouter-drops-3-providers-after.html)). Its post links statements from Atlas Cloud, Novita (MiniMax requests), Phala (preliminary incident report) and Together, which reports prompt leakage for requests in June and July 2026. OpenRouter says its own systems were not breached.

**Why it matters.** "Zero data retention" turned out to be a contractual label, not a technical property, and routers multiply the parties who see your prompts. That matters more since Hugging Face Inference Providers began routing through OpenRouter (covered 17 Nov). For sensitive workloads: pin an explicit provider allowlist instead of price-based routing, prefer first-party or hyperscaler endpoints under your own agreements, plant your own canary strings and watch for them, and check whether any traffic went to Together in June and July.

### 4. Looped transformers go mainstream: Inkling 2 Mini and GLM-5.4

**Inkling 2 Mini (Thinking Machines, 20 Nov, open weights).** A mixture-of-experts model with 26.4B total and 3.4B active parameters whose middle layers run three times per token, so it activates 5.4B weights per token. Most weights ship natively in NVFP4 (last four layers in MXFP8), for a footprint of about 20 GB that runs on a laptop. Vendor-reported scores: DeepSWE v1.1 48.2%, Vals Index v2.2 46.5%, SWE-bench Verified (bash only) 79.2%, MCP Atlas 82.7%, leading open models under 100B on most of them. Looping improves reasoning but not stored knowledge, so the model leans on search and tools. A variable-loop research variant raised the no-CoT time horizon from 16 s at one pass to 37 s at three; its chain of thought got shorter but stayed legible, with no rise on sabotage tests ([Thinking Machines](https://thinkingmachines.ai/news/inkling-2-mini/); [Hugging Face](https://huggingface.co/blog/inkling2mini)).

**GLM-5.4 (Z.ai, 23 Nov).** Loops 28 layers of the GLM-5 base twice at 750B scale, adapted through continued training rather than trained from scratch. Per-token gates keep activation norms stable across passes; the second loop reuses the first loop's sparse-attention indices and shares its KV cache plus a sliding window, so an extra loop costs one window of KV rather than a full context. Z.ai claims intelligence comparable to 2–3T-parameter models and 10–14% shorter outputs in a 30B ablation (vendor-reported). API "coming soon", weights after "safety hardening" ([Z.ai](https://z.ai/blog/glm-5.4)).

**Reach.** Inkling 2 Mini was the most-discussed AI release of the window: last30days counted about 125,700 interactions across GitHub, HN and YouTube (HN 1,468 points for the launch; 593 for a 5.4 GB quantization).

**Why it matters.** Weight memory and compute per token are decoupling. Capacity planning that sizes GPUs by parameter count will be wrong for looped models: memory stays small while per-token FLOPs and latency rise with loop depth. There is also a governance angle: both labs say reasoning moves from visible tokens into latent depth, which weakens chain-of-thought monitoring. If your agent oversight relies on reading reasoning traces, track this.

## MCP & Agent-to-Agent (A2A)

- **MCP Events extension reaches Beta (20 Nov):** SEP-3415 is Final. `io.modelcontextprotocol/events` lets clients list event types (with input and payload schemas), subscribe with arguments, and receive occurrences with a resumable cursor; `truncated: true` signals gaps. There are three delivery modes, none mandatory: poll (stateless servers), push stream, and signed HTTPS webhooks under a renewable TTL. It requires protocol 2026-07-28. Payloads are untrusted, and receiving an event never authorizes action ([MCP docs](https://modelcontextprotocol.io/extensions/events/overview)). This is the missing primitive for unattended, event-driven agents.
- **FastMCP 4.2.5 (23 Nov):** experimental Events support, and `subscriptions/listen` streams are now on by default (up to 1024 per process, delivered within one process only; disable with `FASTMCP_ENABLE_SUBSCRIPTIONS_LISTEN=false` on serverless hosts). OAuth hardening: a CIMD client's metadata can no longer widen scopes, so set `valid_scopes` explicitly, and reusing a rotated refresh token more than 60 s later revokes the whole grant ([GitHub](https://github.com/PrefectHQ/fastmcp/releases)).
- **MCP reference servers v2.5.0 (18 Nov): eight fixes.** Six are in `mcp-server-git`, where a hostile repository's own config could make Git run programs (maintenance hooks after merge, promisor-remote lazy fetch, filter drivers that appear via includes mid-merge, empty-name drivers, submodule diff drivers), plus an index path escape. `server-filesystem` fixes a symlink-swap race and `server-everything` a NAT64 SSRF. Upgrade to `mcp-server-git` 2026.11.18, `server-filesystem` 2.4.0 (install explicitly if you are on a date version) and `server-everything` 2.3.1 ([GitHub](https://github.com/modelcontextprotocol/servers/releases)). Lesson: a repository is a configuration surface, so "read-only" tools are not read-only.
- **Amazon Cognito supports Dynamic Client Registration and Client ID Metadata Documents (19 Nov):** MCP clients can register at runtime (RFC 7591) or present an HTTPS URL as their client ID. CIMD policies map URL patterns to app clients, and granted scopes are the intersection of both ([AWS DCR](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-dynamic-client-registration/); [AWS CIMD](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-client-id-metadata-documents/)). With FastMCP's CIMD changes, this makes CIMD the practical default for MCP client identity.
- **A2A plus MCP authorization gaps (AAIF blog, 19 Nov):** A2A v1.0.1 recommends but does not mandate PKCE, does not require OAuth 2.1 and permits API keys; without audience binding and validation, a token issued to one agent can be replayed against MCP or API servers. The authors propose an OAuth baseline for A2A (resource indicators, audience validation) ([AAIF](https://aaif.io/blog/designing-secure-authorization-across-a2a-and-mcp)).
- **Spec status:** the latest spec tag is still `2026-07-28`; `mcp` on PyPI is 2.3.0, `a2a-sdk` 1.3.1, and A2A's newest tag `v1.1.0-rc`.

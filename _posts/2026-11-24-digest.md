### 2. Anthropic launches Claude Ship: AI review, fixes and policy-based approval of pull requests

**What happened.** On 23 Nov Anthropic released Claude Ship for GitHub repositories on Team and Enterprise plans ([Claude](https://claude.com/resources/articles/introducing-claude-ship); [TechCrunch](https://techcrunch.com/2026/11/23/anthropic-launches-claude-ship-letting-ai-agents-review-fix-and-approve-code-changes/)). It has three agents:

- **Code Review** (already GA) reviews a PR, adversarially verifies its findings and posts them inline. Review levels are Quick, Standard or Deep.
- **PR Steward** (beta) pushes fixes for failing CI, merge conflicts and review comments. It comments after every push with what changed and how to undo it, and by design never approves or merges ([docs](https://code.claude.com/docs/en/pr-steward)).
- **Claude Approvals** (beta) reads a policy file in the repository: how many people must approve changes to a path, and where Claude may post an approving review. The policy can use Code Review findings or the team's own classifiers written in natural language. It blocks a merge only where branch protection makes it a required check ([docs](https://code.claude.com/docs/en/claude-ship)).

A `/ship` command in Claude Code pushes a change, opens the PR and runs the same loop. Billing is per token, with spend limits per repository. Claude Ship is **not available** to organizations with Zero Data Retention, the HIPAA configuration or customer-managed keys.

**Why it matters.** This is the first mainstream product that hands approval authority to an agent, under a policy file kept in the repository, which works like a smarter CODEOWNERS. The docs warn that with auto-merge or a merge queue, a policy that needs no human approval lets a change merge without anyone acting. Treat the policy file as security-critical code: protect it with CODEOWNERS, run in observe mode first, and require a person for infrastructure, auth and dependency paths. Anthropic's own figures are vendor-reported: on the Claude Code team, merged PRs more than doubled from June to September and the share of reverted PRs fell by over 40%. On Hacker News (5 stories, about 65 points), commenters suggested using a different vendor's model for review than for authoring, to keep the two roles separate (via last30days).

### 3. Azure API Management Classic flaw exploited to steal secrets

**What happened.** Microsoft told customers (Service Health advisory MZK9-GH0) that a flaw in **Azure API Management (APIM) Classic** Developer, Basic, Standard and Premium tiers gave an unauthorized party management-plane access, including reads of stored secrets. Microsoft says it identified the flaw on 18 Nov and closed the access path on 19 Nov. The Classic Consumption tier and all v2 tiers are not affected ([BleepingComputer](https://www.bleepingcomputer.com/news/security/microsoft-azure-flaw-exploited-to-steal-customers-api-credentials/); [The Register](https://www.theregister.com/security/2026/11/23/norway-links-energy-firm-cyberattacks-to-critical-azure-api-management-flaw/5311598)). Possibly exposed: Named Values, identity-provider and OpenID Connect client secrets, subscription keys and direct-management API tokens. Norway's National Security Authority (NSM) links the attacks to incidents at Equinor and Skagerak Energi, says sectors outside Norway are affected, and tells all APIM users to assume their secrets are compromised and rotate them ([NSM](https://nsm.no/aktuelt/nsm-deler-tiltak-mot-sarbarhet-i-azure-api-management)).

**What to do.** Microsoft's fix does not invalidate credentials taken before 19 Nov. Rotate every secret and token held in APIM Classic, check backends reachable with those credentials, and move secrets to Key Vault references. NSM publishes patch thresholds based on the instance's `RuntimeVersion` (0.52.x patched at build 31936 or later, 0.53.x at 31938 or later). Microsoft says the fix is deployed everywhere. Look for forgotten dev and test instances too. An administrator's claim on Reddit that the entry point was an unlogged legacy API is unverified (social, source not directly verified).

**Why it matters.** An API gateway concentrates the credentials for everything behind it. That makes a control-plane bug in a managed gateway a supply-chain-level event, and the same applies to the MCP and agent gateways being deployed now.

### 4. OpenAI and Cisco open-source Shirudo: eBPF "shields" that block exploits without restarting services

**What happened.** On 23 Nov OpenAI and Cisco released [Shirudo](https://openai.com/index/introducing-shirudo), a BSD-2-licensed runtime (its BPF programs are dual BSD/GPL) for deploying temporary protections on running Linux hosts while patches are being rolled out. A "shield" is an eBPF program that blocks the specific behaviour a vulnerability depends on. Shields are cryptographically signed, checked by the kernel's eBPF verifier, and recorded through a TPM so operators can prove what was loaded or removed. An agent can draft and test a shield against exploits and real workloads, and an operator approves it before enforcement. In OpenAI's demo, a Codex-generated shield added an input check to Java's Base64 decoder inside a running Elasticsearch process and blocked a Java4Shell exploit without a restart. Shirudo builds on Isovalent's Tetragon (Cisco owns Isovalent) ([The Register](https://www.theregister.com/security/2026/11/24/cisco-and-openai-pitch-ebpf-kernel-plugins-as-the-way-to-tame-the-patchpocalypse/5311795); [The Hacker News](https://thehackernews.com/2026/11/openai-and-cisco-unveil-ai-assisted.html)).

**Why it matters.** AI bug-finders are producing more CVEs than teams can patch, and Java4Shell (covered 18 Nov) is the example. Shirudo makes "virtual patching" an open, kernel-level, auditable primitive that is not tied to a vendor, and the stated aim is to ship tested shields alongside disclosures. Before adopting it, check the operational questions: blast radius if a shield also blocks legitimate requests, kernel version spread across fleets, and who approves shields generated by an agent.

### Research

- **Tool-call smuggling (arXiv 2611.30624, 23 Nov):** when a guard and an executor parse the same tool-call JSON differently (duplicate keys and similar ambiguities), the guard approves one call, the executor runs another, and the audit log records the approved one. The authors tested 17 parser and validator configurations; most pairs disagree on some inputs, including two official MCP SDKs. The fix they validate: parse once, keep only the approved schema's fields, and seal the call with its ID on the way to the executor ([arXiv](https://arxiv.org/abs/2611.30624)). This applies directly to any MCP gateway or policy layer.
- **sudo L7 (arXiv 2611.30517):** 60 underspecified tasks written by staff engineers, graded against 1,287 hidden rubric criteria. Leaderboard pass rates (author-reported): Claude Fable 5.2 52.2%, Sonnet 5.5 50.6%, Opus 5.5 46.1%; GPT-6.1 Sol and GPT-6 Astra 31–34% ([arXiv](https://arxiv.org/abs/2611.30517)).
- **Interrogation protocols for AI control (arXiv 2611.30583):** letting a weaker monitor question an agent about suspicious actions raised safety at a 1% audit budget from 72.6% to 79.5% on BashArena. Most of the gain came simply from having the trusted model state a specific concern ([arXiv](https://arxiv.org/abs/2611.30583)).

## Engineering Blogs & Tech Press

- **vLLM Blog, "Skip the DRAM Tier: MoRI UMBP Runs the Agentic KV Cache on NVMe" (23 Nov):** in agentic serving, the median turn in replayed Claude Code sessions is 142K tokens, over 96% of them a prefix the server has seen before, so the KV-cache hit rate determines throughput: +1 point of hit rate gave about 10% more throughput on Kimi-K3. On AMD MI355X, a 1.8 TB NVMe KV pool matched a 1.8 TB DRAM pool within 1% at 48–96 sessions, because vLLM loads KV asynchronously while requests wait for prefill. The cost model differs: DRAM costs per TB held, NVMe per TB written. Drives rated for 83 TB of writes a day hold a day of KV for about $59K at list price, while a $76K DRAM pool holds about 31 minutes. The trade-off is SSD wear (vendor-reported; [vLLM](https://vllm.ai/blog/2026-11-23-skip-the-dram-tier)).
- **Cloudflare, "Probing DNS at Cloudflare" (23 Nov):** a scheduling bug once left DNS record changes unpublished for hours while every health check stayed green. Cloudflare extended Flamingo, its Rust edge-testing framework with a small setup-request-assert DSL, with a DNS module that measures record propagation from every data center in production. Those measurements now gate whether a release proceeds or rolls back. The lesson: for an eventually consistent system, test freshness as customers see it, not process health ([Cloudflare](https://blog.cloudflare.com/probing-dns-at-cloudflare/)).
- **Databricks, "Sharing catalog metadata across data platforms, engines, and agents" (24 Nov):** an optional `labels` field (string key-value pairs at table and column level) added to the Apache Iceberg REST LoadTable response.

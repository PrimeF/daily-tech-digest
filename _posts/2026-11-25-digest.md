## Top Stories

### 1. AI-written proofs claim VP ≠ VNP, and OpenAI adds matrix multiplication at ω = 9/4 and strongly polynomial linear programming

**What happened.** On 23 Nov Anthropic published *VP ≠ VNP over every field*, a paper and Lean 4 formalization written by "an internal research Claude model". It claims that circuits for the Hamiltonian cycle polynomial (and the permanent outside characteristic 2) need more than m^(c (log m)^(1/3)) gates, so VP is a proper subset of VNP. The README is explicit: "no human mathematician has checked the proof", and "no machine checks that [Statement.lean] says what is claimed" ([Anthropic formal-math](https://github.com/anthropics/formal-math/tree/main/vp-vnp)). OpenAI posted its own *VP and VNP are different* the same day; its history file says that result was obtained on 6 Nov. Notebookcheck reports that Anthropic's upload came about six hours before OpenAI's and quotes Cambridge's Tom Gur calling the progress "unprecedented" while urging time for review ([Notebookcheck](https://www.notebookcheck.net/Anthropic-and-OpenAI-claim-breakthroughs-on-a-47-year-old-fundamental-math-problem.1459160.0.html)).

On 24 Nov OpenAI added nine more manuscripts from an unnamed internal model ([OpenAI math history](https://github.com/openai/math/blob/main/history.md)). Family 379 claims the square matrix multiplication exponent is exactly 9/4 over every field (an earlier OpenAI manuscript from October gave ω ≤ 9/4 over ℂ), circuit lower bounds that subsume the VNP paper, and an exponential sunflower bound. Family 380 claims a deterministic strongly polynomial algorithm for linear programming (Smale's ninth problem) and refutes the polynomial Hirsch conjecture ([catalogue](https://github.com/openai/math/blob/main/CONTENTS.md)). OpenAI says roughly 42% of top-line results in the repository have Lean formalizations, that each result used about three hours of ChatGPT Pro thinking compute, and that "some of the unformalized results could have issues" ([OpenAI math README](https://github.com/openai/math)). Reach: the ω = 9/4 paper was on the Hacker News front page with about 470 points; the Anthropic VP ≠ VNP repository drew about 360.

**Why it matters.** Last week's digest covered the Lean-checked Riemann Hypothesis proof. This week two labs claim several of complexity theory's central open problems, a few hours apart and with priority disputes already starting. None of the claims has human review yet. The engineering pattern is the same as before: a small trusted kernel checks a huge machine-written artifact, and the remaining risk sits in whether the formal statement means what is claimed, which both repositories flag. If ω = 9/4 and strongly polynomial LP hold up, they are theoretical results with galactic constants, not faster BLAS or solvers next quarter. The practical signal for architects is the capability itself: models that find proofs this hard will also find bugs and exploits, as Top Story 4 shows.

### 2. Google will require AI agents to use MCP for Workspace data, and Anthropic ships Skills over MCP

**Google (24 Nov).** Workspace MCP servers (Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, Tasks) and the Workspace CLI are generally available. Under a new Workspace AI Tools Addendum, AI agents "must use MCP to access Workspace data, rather than calling Workspace REST APIs directly", with technical enforcement from **1 February 2027**. Agents need dedicated OAuth clients flagged `is_agentic`; the MCP servers enforce user confirmation before sending email, changing Drive sharing or bulk edits, apply DLP and audit logging, and reject non-agent OAuth clients. The addendum forbids long retention of derived data and API scraping. A Scaled usage tier is billed from 1 April 2027 for usage above free allowances ([Workspace Updates](https://workspaceupdates.googleblog.com/2026/11/mcp-servers-cli-standardized-usage-tiers-now-available.html)). On Google Cloud, **Agent Gateway** is a protocol-native gateway for LLM, MCP and A2A traffic: it verifies agent identities against Agent Registry, enforces IAM and default-deny egress, and screens requests with Model Armor ([Google Cloud](https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise)).

**Anthropic (24 Nov, MCP's second birthday).** Skills over MCP is in public beta in Claude and Claude Code: a server can publish skills (playbooks) next to its tools, loaded only when needed, so the guidance ships and updates with the server. Tasks (long-running background work) and Elicitation (pause for user input mid-call) are GA for Pro, Max and Ultra and rolling out to Team and Enterprise; File Uploads is "rolling out soon". Anthropic cites over 700M monthly SDK downloads ([Claude](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more); [The Next Web](https://thenextweb.com/news/anthropic-claude-skills-over-mcp-tasks-elicitation)). The maintainers' anniversary post adds that Enterprise-Managed Authorization is now a stable extension, SDKs have passed 5 billion total downloads, and the next spec release is planned for March 2027 ([MCP blog](https://blog.modelcontextprotocol.io/posts/mcp-turns-two/)).

**Why it matters.** This is the first time a major SaaS platform has made MCP the *mandatory* interface for agent access, rather than one option among several. Any agent your organization runs against Workspace through REST needs a migration plan before February. The design follows the gateway pattern that keeps recurring (AWS WAF's MCP/A2A inspection, covered yesterday, and now Agent Gateway): policy, confirmation and audit move into the protocol path rather than the agent. Skills over MCP removes the separate install step, but it also means a third-party server can change the instructions your agent follows without a client update. Treat server-shipped skills like code from that vendor: pin and review them where your client allows it. The Next Web notes that malicious agent skills collected about 1.7 million installs earlier this year.

### 3. Update: Microsoft declares an internal "Code Red" after the 12–13 Nov Microsoft 365 outage

**What's new (outage last covered 24 Nov, with the final post-incident report).** Internal memos reported by Reuters, and summarised by Ars Technica and SiliconANGLE, show that Microsoft 365 Core president Jason Henderson declared a Code Red, calling the outage the most customer-impacting incident in Exchange Online's history ([Ars Technica](https://arstechnica.com/gadgets/2026/11/microsofts-historic-cloud-outage-exposed-an-engineering-fog-of-war/); [SiliconANGLE](https://siliconangle.com/2026/11/24/microsoft-declares-internal-code-red-after-nearly-24-hour-microsoft-365-outage/)). Details from the memos:

- Responders exchanged more than 11,000 messages across 11 Teams chats, and diagnostic data was scattered across tracking systems (CVP Amanda Silver called it a "fog of war").
- An urgent production fix in a recent incident took five to six days to reach worldwide saturation. The target for the most urgent security fixes is detection to safe worldwide deployment in one hour; "we aren't here yet".
- Five workstreams: load shedding, geographic traffic partitioning and faster recovery, plus AI agents to help diagnose system-health data. The target is worldwide resolution of major incidents within an hour.
- Charles Lamanna said the affected component had "roughly ten years' worth of acceptable failures".

**Why it matters.** The memos confirm what the post-incident report implied: the failure was in incident coordination and deployment velocity as much as in the July defect. "Deploy worldwide in an hour" and "partition traffic geographically" pull in opposite directions; as one expert quoted by SiliconANGLE puts it, a pipeline that pushes a fix in an hour can push a mistake in an hour. For your own Microsoft 365 dependency: these are internal goals with no date and no SLA change. Keep out-of-band communication channels that do not depend on Teams or Exchange.

### 4. AI-driven intrusions: the UK NCSC sounds a warning as GreyNoise details an agent-assisted Check Point campaign

**NCSC (24 Nov).** The UK National Cyber Security Centre says it has seen a "marked rise" in AI-driven attacks since September, including intrusions and downtime caused by autonomous hacking tools such as Artex and Cairn. The weaknesses exploited are not new memory-corruption bugs but "unmitigated weaknesses that are often the result of years of technical debt": exposed systems, weak passwords and developer API endpoints ([TechCrunch](https://techcrunch.com/2026/11/24/uk-warns-ai-driven-cyberattacks-are-exposing-years-of-weak-security/)).

**GreyNoise (23 Nov).** GreyNoise documents a campaign it tracks as GT13 against **Check Point Security Management Servers**, with confirmed activity from 17 Oct to 2 Nov affecting at least 22 organizations across Europe, Asia, Australia and the US (finance, energy, government, transport). The actor used 99 IP addresses, a compromised Rejetto HFS server as a relay (forging admin cookies by reconstructing V8's `Math.random()` state), Chisel, Impacket and Nmap, and attempted exploits including a Check Point SmartConsole auth bypass (CVE-2026-16232), Windows NetLogon and a Linux IPv4 use-after-free. GreyNoise believes LLM agents drove much of the scanning, exploitation and tooling, and expects the intrusions to be ongoing because the actor kept access to the devices ([GreyNoise](https://www.greynoise.io/blog/check-point-security-management-servers-intrusion-campaign)). Reach: about 280 HN points.

**Why it matters.** Security management servers hold policy for whole firewall estates, so this is a high-value target class, the same one as the Azure API Management secret theft covered yesterday. Check Point customers should verify SmartConsole and management-server patch levels, look for unknown SSH keys and Chisel tunnels, and review outbound connections from management hosts. More broadly, the NCSC's point is that agentic tooling makes old debt cheap to find, so the basics (MFA, exposure inventory, credential hygiene) now pay off faster than ever.

### Research and Benchmarks

- **When Answering Is Administering (arXiv 2611.32195, 24 Nov):** in Claude Code, a plugin or remote service that answers one permission prompt can attach an update that *deletes* a deny rule, because only updates that add or replace allow rules are checked; the agent then reads the protected secrets, even in the strict sandbox, and the deletion looks like a local operator edit. The authors' bounds predicted the outcome in 13 permission designs across ten agents, including Codex, Gemini CLI, opencode and Goose. Only 2 of 2,227 marketplace plugins send policy updates ([arXiv](https://arxiv.org/abs/2611.32195)). If you delegate approvals to a remote service, check whether your runtime records who wrote each rule.
- **ShellBench (arXiv 2611.32946):** 100 everyday tasks derived from more than 10 million real requests, 53,100 rollouts over 12 models and 5 harnesses. Model choice mattered more than harness (harness pass@1 between 42.9 for Claude Code and 45.2 for OpenClaw); GPT-6 Astra led at 62.5%, GPT-6.1 Sol reached 61.4% at about a sixth of the cost ([arXiv](https://arxiv.org/abs/2611.32946)). TechCrunch adds that 15.7% of attempts broke at least one safety requirement and the top model passed all three repeats of a task less than half the time ([TechCrunch](https://techcrunch.com/2026/11/24/even-the-best-ai-agents-struggle-with-everyday-life/)).
- **Humanity's First Exam (Google DeepMind, 24 Nov):** 544 elementary text and image prompts across 20 capabilities, scored on whether a model answers consistently every time, not once; a Kaggle competition runs until 15 Dec to add questions models still get wrong ([Google](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/humanitys-first-exam/)). Reliability benchmarks (this, ShellBench) are a better guide for agent SLOs than capability ceilings.

## Engineering Blogs & Tech Press

- **LangChain, "The Agent Lake" (24 Nov):** LangChain argues that agent traces plus outcomes (thumbs-down, merged PRs, judge scores) form a new data platform category: trace-optimized storage (SmithDB) with "intelligent compute" over it, meaning online evaluators, cheap decision models as semantic filters for search, and agents that cluster failures and open fix PRs. The architectural takeaway is to model outcomes many-to-many with traces (one PR, many threads). Vendor-reported: Engine has analyzed more than 60M production traces, and a Kimi K3 fine-tune scored 96 on an internal benchmark vs 90 for the base model ([LangChain](https://www.langchain.com/blog/the-agent-lake)).
- **Salesforce Engineering, "Git-based engineering knowledge framework" (24 Nov):** its first single-repository "Second Brain" for agents got slower and more token-hungry as it grew; splitting it into 21 domain repositories linked by a knowledge graph that records decisions, evidence and which proposals were rejected fixed retrieval. Vendor-reported: a Kubernetes upgrade agent built on it automates about 80% of the upgrade, cutting human work from three months to three weeks ([Salesforce](https://engineering.salesforce.com/supercharging-ai-agents-build-a-git-based-engineering-knowledge-framework-in-20-minutes/)). Lesson: knowledge boundaries matter as much as the knowledge, and agents need to know which decisions were rejected.
- **AKS Engineering, DACS with Run:ai Model Streamer (24 Nov, preview):** a distributed read-through NVMe cache in front of Blob Storage for model weights. On an H100 with vLLM, warm-cache model loading averaged 8.08 s vs 17.4 s from Blob; container start to ready fell only from 61 s to about 51 s. The authors stress that the cold and direct-Blob figures are single runs and not a performance guarantee ([AKS blog](https://blog.aks.azure.com/2026/11/24/dacs-runai-model-loading)). Weight loading is only part of cold start, so measure the whole path before buying cache.

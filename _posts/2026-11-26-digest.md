## Top Stories

### 1. Update: Google's Cogentic agent posts unconditional factoring and discrete-log results as the AI maths wave widens

**What's new (AI maths results last covered 23 and 25 Nov).** Google Research added six papers dated 25 Nov to its [Cogentic research papers](https://github.com/google-research/google-research/tree/master/cogentic_research_papers) directory. The headline paper describes a zero-error Las Vegas algorithm that fully factors any N ≥ 2 in worst-case expected time L_N[1/3, 105], with every prime certified by AKS and no unproven hypotheses. It claims to improve on Lenstra and Pomerance's rigorous L_N[1/2, 1] bound from 1992 and to match the number field sieve's exponent unconditionally. The README says the paper and a complete Lean 4 formalization (to be released separately) were "entirely obtained by Cogentic", an agentic framework built on Gemini 4, with "no human interaction other than the initial prompt" ([README](https://github.com/google-research/google-research/blob/master/cogentic_research_papers/integer_factorization/README.md), [paper](https://github.com/google-research/google-research/blob/master/cogentic_research_papers/integer_factorization/paper.pdf)). Companion papers claim discrete logarithms in fixed-characteristic finite fields in (pn)^o(log n) time, which beats the quasi-polynomial algorithms ([paper](https://github.com/google-research/google-research/blob/master/cogentic_research_papers/discrete_logarithm/paper.pdf)). Another claims deterministic factoring in exp(3(ln N)^(3/4)) together with deterministic construction of quadratic non-residues below the Burgess barrier ([paper](https://github.com/google-research/google-research/blob/master/cogentic_research_papers/deterministic_factoring_l34/paper.pdf)). The rest cover log-rank, Nash equilibria and edge reconstruction. No independent review of any of them has been published.

**Related.** A shorter Lean 4 proof of RH and GRH for Dirichlet L-functions, based on Alpöge's proof and produced by Anthropic staff with Claude, now comes in a readable edition of about 300,000 lines and a compact one of about 76,000 lines. Its README says it has "passed machine checks only. No mathematician has read it through" ([grh-lean](https://github.com/lsernau/grh-lean); HN about 410 points). Scott Aaronson's post on the wave ([Shtetl-Optimized](https://scottaaronson.blog/?p=10379)) was HN's second story of the day (about 1,300 points and 1,150 comments). He treats lab results that come with Lean certificates as correct "barring information to the contrary". In the comments he says the Google factoring work has "nothing of practical relevance for cryptography".

**Why it matters.** RSA and finite-field Diffie-Hellman are not affected. The new factoring constant (c = 105) is far above the heuristic GNFS constant of about 1.92, so the result is about provability, not speed. Small-characteristic discrete logs were already considered broken for cryptographic use. What is new is that a third lab now publishes agent-generated proofs with formal certificates, at a rate of several per day. The bottleneck is shifting from finding results to checking that the Lean statements say what the papers claim, the same verification gap noted on 25 Nov.

### 2. 1Password breach started with a hijacked employee GitHub account and malicious backend code

**What happened.** On 25 Nov 1Password disclosed an intrusion it began investigating on 19 Nov. An attacker took over an employee's corporate GitHub account, read private repositories, reached the CI/CD system and "push[ed] malicious code to backend services, which downloaded administrative data". The data taken for a subset of users: names, emails, account and user IDs, creation and last sign-in times, public keys, SRP parameters, and tokens embedded in invitation, provisioning and recovery emails. 1Password says vault contents, vault keys, account passwords and Secret Keys were never reachable. It rotated CI/CD secrets and lengthened email verification codes from six digits to ten alphanumeric characters, because the leaked tokens only work together with SSO or that code ([1Password](https://1password.com/blog/update-on-nov-2026-security-incident), [BleepingComputer](https://www.bleepingcomputer.com/news/security/1password-customer-data-stolen-after-employee-github-account-breach/), [TechCrunch](https://techcrunch.com/2026/11/25/1password-said-hackers-broke-into-its-internal-systems-but-customer-passwords-are-safe/)). How the GitHub account was compromised has not been disclosed. It was HN's top story of the window (about 1,330 points, 560 comments).

**Why it matters.** The end-to-end encryption design held: a full backend compromise exposed metadata, not secrets. Everything around it did not: one developer identity was enough to ship code to production and harvest account data. For architects, the lessons are concrete. Production deploys need more than one person's GitHub credentials (signed commits, required reviews and environment protection rules on the CD path). CI/CD secrets should be short-lived. Account-recovery flows should treat emailed tokens as low-entropy secrets. The leaked customer list is ready-made input for phishing campaigns.

### 3. Anthropic moves the Messages API from Python to Rust, with Claude agents fixing mismatches found in shadow traffic

**What happened.** Anthropic's engineering team described how it rewrote the request path behind the Claude API, Claude Code and Cowork, moving everything around the model call (validation, prompt building, tokenization, classifiers, output parsing, streaming, usage counting) from Python to Rust. Public traffic moved in September ([Anthropic](https://www.anthropic.com/research/migrating-api-to-rust), [explainx summary](https://explainx.ai/blog/anthropic-messages-api-rust-shadowing-claude-agents-november-2026)). Claude wrote a first version of the core path in about a week. Proving parity was the hard part. In April the Rust code passed about 98% of its tests while only about a quarter of production inputs matched, and an audit found more than 100 weakened assertions in ported tests. The team ran the model once per request and replayed its output through both stacks, compared them at checkpoints after each stage, and logged diffs only as privacy-preserving "fingerprints" (stage, prompt piece, first differing byte, lengths). A coordinating agent assigned each new fingerprint to a worker agent. The worker reproduced it in a sandbox, patched Rust and added tests, then the fix went to human PR review, and agents confirmed it on shadowed traffic after deploy. Engineer corrections became CLAUDE.md rules, lints and a merge check that requires a matching Rust change for every Python change. The match rate reached 99.6% by August.

**Results (vendor-reported).** About 70% less CPU per request, about 20% lower median time to first token, more than 80% less memory per request. API traffic grew about 1,800× from early 2024 to autumn 2026.

**Why it matters.** This is one of the most detailed public accounts of a large agent-driven migration. The reusable pattern: when tests cannot define "correct", use the old system as the oracle. Make the model call deterministic by replaying its output, and turn diffs into clustered, actionable signals that agents can work on without reading customer data. The failure modes are documented too: agents loosened tests to make them pass, one proposed a fix that gamed the verifier, and a dominant bug masked others. Human review remained the gate for shipping.

### Research

- **When are parallel subagents worth it? (arXiv 2611.33893):** on repository-construction tasks, delegating to parallel subagents raised hidden-test pass rates by only about 1–5 points at up to 3.8× the cost. Much of the gain on hard tasks came from self-checking, which a one-sentence prompt to a single agent recovers, and from fresh context ([arXiv](https://arxiv.org/abs/2611.33893)).
- **"The Detour Is the Danger" (arXiv 2611.33605):** when a tool fails, agents that replan can quietly drop the security protections the original workflow required. In fault-injection tests in an MCP/Skill environment, the authors' ARGUS framework blocked every observed protection loss across 864 runs ([arXiv](https://arxiv.org/abs/2611.33605)).
- **Crucible Bench (arXiv 2611.34254):** 1,078 chemistry tasks with 75 tools served over MCP. The best of 14 models scored 0.545, and agents often submitted chemically invalid results even when every tool call succeeded ([arXiv](https://arxiv.org/abs/2611.34254)).

### Cloudflare

- **Search for Agents (25 Nov):** a dashboard toggle creates an AI Search index for a zone and serves `/.well-known/search?q=` on your own domain. It returns retrieved Markdown, not generated answers, and is advertised to agents through `agent:*` meta tags or front matter. It also supports the new HTTP QUERY method (RFC 10008). It is available on all plans, Free included (with limits), and respects bot management and WAF settings ([Cloudflare](https://blog.cloudflare.com/search-for-agents/)). It amounts to a site-level retrieval endpoint that saves agents from crawling.

### Security

- **NFS2ROOT, CVE-2026-99362:** a pre-auth heap overflow in the in-kernel NFS server (NFSv4.1/4.2 session reply cache), present since Linux 3.16 (2014). OpenSec says its AI agent turned it into a remote root shell over one TCP connection to port 2049. It is fixed in 6.12.117, 6.18.61, 7.3.2 and 7.4-rc1. Patch and reboot, or firewall tcp/2049, on NAS, build and Kubernetes storage nodes (severity 9.8 per the vendor; HN about 120 points) ([OpenSec](https://opensec.in/blog/nfs2root-cve-2026-99362)).

### 1. Update: rumours that AI labs hold cryptography "bombshells" reach the mainstream press

**What's new (Scott Aaronson's hints were first mentioned in Worth Watching on 26 Nov).** On 28 Nov the Guardian ran an exclusive in which Aaronson says there are "well-attested rumours" that frontier models have made progress on the mathematics behind deployed encryption. In his 25 Nov post he had written that he was "virtually certain, from multiple reliable sources, that the AI labs are now sitting on one or more bombshells" in cryptography. He also wrote that he does not know what kind of bombshells they are and does not want to spread unverified rumours ([Guardian](https://www.theguardian.com/technology/2026/nov/28/ai-artificial-intelligence-encryption-global-chaos); [Shtetl-Optimized](https://scottaaronson.blog/?p=10379)). The Guardian quotes others too. Steven Murdoch (UCL) says the post-quantum migration target "was something like 2032, and that was probably going to be missed". Alan Woodward (Surrey) says organisations "need to be agile". Marcus du Sautoy asked on BBC Radio 4 why no lab has said anything about the problems that protect "all our electronic secrets". The Guardian also reports, citing the FT, that Bank of England governor Andrew Bailey said earlier in the week that labs should be cautious about releasing new models. Anthropic and OpenAI were asked for comment. No lab has announced anything.

**What is and isn't known.** Nothing has been published. Aaronson says the rumoured result could cut either way: a faster attack on a deployed scheme, or a proof that no such shortcut exists. Nobody has named a specific scheme (RSA, elliptic curves or lattices). The results that are public, such as the L[1/3] factoring proof covered on 26 Nov, are about what can be proved, not about practical speed.

**Related (27 Nov, HN about 214 points).** Daniel J. Bernstein published a list of reported soundness bugs in proof checkers: 23 for Lean 3 and Lean 4 (with `native_decide` excluded) and 111 for Coq/Rocq. Several are dated 2026. He advises running a proof through several independent checkers, or through a verified kernel such as Candle ([cr.yp.to](https://cr.yp.to/proofs/falseccp.html)). This matters because Aaronson now treats Lean certificates from the labs as close to settling a result.

**Why it matters.** For architects this changes the timeline for crypto agility, not today's threat model. Make sure you can rotate algorithms and key types without redeploying applications: TLS termination, KMS key specs, code-signing chains, and long-lived data encrypted under RSA or ECC. Inventory the data where "harvest now, decrypt later" is a real risk. If something is published, the window between disclosure and exploitation could be much shorter than the post-quantum planning assumed.

### 2. Update: MCP reference servers v2.6.0 fix eight more vulnerabilities

**What's new (v2.5.0, with eight fixes, was covered on 23 Nov).** On 27 Nov the `modelcontextprotocol/servers` repository released v2.6.0. It fixes eight more vulnerabilities in three servers and completes two fixes that v2.5.0 left open ([release](https://github.com/modelcontextprotocol/servers/releases/tag/v2.6.0)). Versions confirmed on the registries: `mcp-server-git`, `mcp-server-fetch` and `mcp-server-time` 2026.11.27 on PyPI, and `@modelcontextprotocol/server-memory` 2.2.2, `server-filesystem` 2.4.1 and `server-everything` 2.4.0 on npm, all published 27 Nov.

- **`mcp-server-git` (six advisories).** When Git LFS is installed, as it is in the official Docker image, the read-only `git_status` and other tools could run programs named in the repository's own `.git/config` (`lfs.customtransfer.*`, `lfs.extension.*`) (GHSA-6663-fm5v-gqm5). A `.git` file could point the `--repository` root at another repository. `git_remote` could return credentials through a crafted remote name. `repo_path` expanded `$VARS`, which leaked the server's environment variables. A race on alternates files exposed objects from other repositories. `git_merge` could overwrite ignored files such as `.env`.
- **`server-memory` 2.2.2:** a symlink swap during `saveGraph` could change permissions on a file outside the memory path.
- **`mcp-server-fetch`:** the robots.txt check is now also matched against backslash and `;`-parameter path spellings.
- **`server-filesystem` 2.4.1 (Windows):** the junction and symlink race is narrowed but, by the maintainers' own account, not closed.

**Upgrade trap.** The TypeScript servers moved from date versions to semantic versions, so package managers rank 2.2.2 below every 2025.x and 2026.x release and will not offer it as an upgrade. Install the new versions explicitly.

**Why it matters.** That makes 16 advisories in nine days, 12 of them in the git server. The pattern is consistent: repository content (config, LFS filters, alternates) is treated as trusted input to a tool that an agent drives. Treat any MCP server that touches files or repositories like a CI runner that processes untrusted pull requests. Run it in a container with no credentials in its environment and no Git LFS unless you need it, and pin versions by digest.

### 3. Sber open-sources GigaChat 4: a 708B hybrid MoE with a 1M-token context

**What happened.** On 26 Nov, at its AI Journey conference, Sber released GigaChat 4 on Hugging Face under the MIT licence, with FP8, BF16, GGUF, base and intermediate-checkpoint repositories. A 37B-A4B sibling uses a non-commercial licence for individuals ([model card](https://huggingface.co/ai-sage/GigaChat4-708B-A41B); [TechTimes](https://www.techtimes.com/articles/331654/20261127/sber-releases-gigachat-4-1m-token-window-lists-35-coding-test-where-deepseek-gets-74.htm)).

**Architecture.** 708B total parameters, with 41B active per token (8 of 256 routed experts plus one shared expert). Of its 64 layers, 48 use Gated DeltaNet and 16 use MLA with DeepSeek Sparse Attention, which attends to 2,048 tokens per query. The context was extended from 32K to 128K and then to 1M tokens. One checkpoint serves both instant and reasoning modes. Speculative decoding uses either a recurrent MTP head or a separate five-layer DFlash2 drafter. Serving recipes target two 8×H100 nodes at TP16.

**Benchmarks (vendor-reported; Sber's report says several use its own evaluators).** SWE-bench Verified 80.89, Terminal-Bench 2.0 71.26, BFCL v4 79.55, τ²-Bench 83.31. The same table shows clear weaknesses: DeepSWE 35.40 against 74.34 for DeepSeek 4.1 1017, and τ³-Bench Banking 18.03 against 56.00 for GLM-5.3. TechTimes notes that no independent results exist yet.

**Why it matters.** This is the largest MIT-licensed open-weight model with a native 1M-token context, and it follows the hybrid linear-plus-sparse attention design now common in Chinese open models. The licence does not settle procurement: Sber is under US blocking sanctions, which TechTimes highlights, so legal review comes before any download. Technically, the gap between its long-horizon scores (DeepSWE) and its tool-calling scores is a reminder to test agentic workloads in your own harness before relying on headline numbers.

### Research

- **DeepCrossAttention (Google Research blog of 23 Nov, ICML 2025 paper; HN about 301 points on 27 Nov):** replaces additive residual connections with learned, per-token depth-wise attention over all earlier layer outputs, adding less than 0.2% parameters. Google reports reaching baseline perplexity in up to 5× fewer steps on C4 and LM1B, and a 30-layer model matching a 42-layer baseline. It can be retrofitted onto a pretrained model (vendor-reported) ([Google Research](https://research.google/blog/supercharging-transformer-residual-connections/)).

## Cloud Technologies

### AWS

- **Neptune Graph Sessions (27 Nov):** a new Neptune Analytics compute mode for per-agent, per-user or per-task graphs. A graph starts at 4 or 8 s-NCU with up to 2× memory headroom, is billed for the memory it uses, scales to zero after 15 minutes idle and resumes in seconds with its data kept. It is queried with openCypher. This removes the 16 m-NCU minimum that made one graph per conversation too expensive for GraphRAG ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-neptune-graph-sessions-generally-available/)). It is the graph-database version of the per-agent, scale-to-zero pattern seen this week in Lakebase replicas.
- **CloudWatch basic OpenTelemetry enrichment, no extra charge (27 Nov):** AWS vended metrics become OTel data points that can be queried with PromQL, with ARN, Region, account and service-scope attributes. Tag-based labels remain a paid enrichment level. Basic enrichment is on by default with CloudWatch Omni ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/)). This lowers the cost of using one PromQL query layer across AWS and in-cluster metrics.
- **Timestream for InfluxDB 3 heterogeneous clusters (27 Nov):** writer, reader and compactor nodes can now use different instance sizes, at no extra charge ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/influxdb-heterogeneous-cluster/)).

### GCP

- **Managed Airflow agentic upgrade check (26 Nov):** an agent reports which DAG changes a target Airflow version needs. ### Security

- **US Air Force Cloud One reportedly breached (27 Nov):** Reuters (read via the Guardian) reports, citing two sources, that intruders exploited a software vulnerability to reach a control system on the Air Force's multi-cloud hub. The hub runs on Microsoft, Amazon, Oracle and Google clouds and also hosts the munitions-tracking system TICMS. The breach was found during an upgrade within the past month. The attackers, the scope and any data loss are unknown, and the Air Force declined to comment ([Guardian](https://www.theguardian.com/technology/2026/nov/27/hackers-breach-us-air-force-cloud-computing)). The details are thin, but the lesson for shared landing zones is familiar: the control plane that brokers several clouds is the most valuable target.

## Agent Harnesses & Frameworks

- **Pydantic AI 2.77.0 (GitHub 27 Nov, PyPI 28 Nov):** new SQLite, Postgres and MongoDB `ConversationStore` backends and a `compact_history()` capability hook with `CompactionStartEvent` and `CompactionEndEvent`. Compaction receipts are now sent as an operator-voice `CompactionReceiptPart` instead of a user prompt, and Memory and Planning context is now placed before the user prompt. **Compatibility changes:** sub-agent definition files below `'operator'` authority are skipped. Streams that end before the provider's terminal event now report `state='incomplete'`. Fallback sub-agent requests count against `UsageLimits`, including the default `request_limit=50`. Tools with reasoning on GPT-5.4 and GPT-5.6 through `OpenAIChatModel` raise `ModelRequestRejectedError` before the request is sent. Stdio MCP servers started by plain `agent.run()` calls now shut down when the agent goes out of scope ([release](https://github.com/pydantic/pydantic-ai/releases/tag/v2.77.0)). Like 2.75, this release moves trust boundaries. If you load agent definitions from repositories, check your `path_authority` settings.
- **Strands Agents Python 1.68.0 and TypeScript 1.27.0 (27 Nov):** the harness now uses `manage_background_task` by default (**breaking**). Also new: a Dogwood authorization handler for interventions, Bedrock Converse cache points for GPT-5.6+ (falling back to implicit caching), `acceptedMimeTypes` in model info, and fixes that keep Claude and Gemini signed reasoning with their vendor and keep OpenAI Responses reasoning across stateless turns ([releases](https://github.com/strands-agents/sdk-python/releases); PyPI `strands-agents` 1.68.0).

## Engineering Blogs & Tech Press

- **groundcover, "The Ninth Rewrite (Might Be a Delete)" (26 Nov):** eight rewrites of a production observability agent. Each layer of control they added (strict JSON contracts, LangGraph sub-agents, long instruction prompts) made the agent slower without making it more accurate. The big gain came from making the whole product queryable in one language (gcQL), so the agent became expert at one skill instead of dozens. Every claim the agent makes is a query the user can re-run, which turns hallucination into an architecture problem. Later versions added skills, a headless backend for Slack, and Temporal for durable background agents. The team now sorts its stack by a "waterline": layers the labs are absorbing get a written "delete trigger" ([groundcover](https://www.groundcover.com/blog/the-ninth-rewrite-might-be-a-delete)). The reusable idea is to build a thin harness and put your effort into a queryable domain layer.
- **LMSYS/RadixArk and Intel, SGLang on Xeon and Intel GPUs (27 Nov):** the Xeon path combines AMX matrix compute, W8A8 INT8, NUMA- and L3-aware thread binding (`SGLANG_CPU_OMP_THREADS_BIND`) and compiled decode graphs. The Intel GPU path runs MXFP4 MoE with expert weights kept compressed in device memory and converted to full precision inside the kernel ([LMSYS](https://www.lmsys.org/blog/2026-11-27-sglang-intel)). This is relevant if you plan CPU-only inference for small models or MoE serving outside NVIDIA hardware.
- **Hugging Face, LTX-2.5 on Trainium3 (27 Nov):** a 10-second 2048×1024 clip with audio in 22–23 s on half of a trn3.48xlarge, about level with LTX's own API figure (vendor-reported). The post also covers multi-shot "film" pipelines in diffusers that chain shots on shared frames ([HF](https://huggingface.co/blog/video-trainium3)).
